# Руководство по участию в проекте ODS

Добро пожаловать в проект ODS! Мы рады любым формам участия в развитии документации и компонентов системы. Пожалуйста, ознакомьтесь с основными правилами и рекомендациями ниже.

Этот документ описывает правила участия в развитии документации, шаблонов и инструментов проекта ODS.

## Как помочь

- Сообщайте об ошибках в документации и предлагайте улучшения через [Issues](https://gitlab.com/vvvnik/ods-project/-/issues).
- Предлагайте новые разделы документации или улучшения существующих.
- Улучшайте диаграммы, схемы и визуализацию.
- Участвуйте в обсуждениях и помогайте другим участникам.
- Добавляйте примеры использования и практические руководства.

## Pull Requests

- Перед отправкой Pull Request убедитесь, что документация собирается без ошибок.
- Проверьте корректность AsciiDoc разметки и диаграмм.
- Оформляйте коммиты информативно и понятно.
- Следуйте принятому стилю оформления документации.
- Описывайте изменения в тексте Pull Request.
- Старайтесь делать изменения небольшими и тематически связанными.

## Структура проекта

Проект организован как набор компонентов документации с использованием Antora:

### Основные компоненты

- `components/airport-service/` — документация сервиса аэропорта
- `components/data-processing-engine/` — документация движка обработки данных
- `components/information-system/` — документация информационной системы
- `components/toys-service/` — документация сервиса игрушек
- `components/project-guide/` — руководство по работе с проектом

### Структура компонента

Каждый компонент содержит:

- `antora.yml` — конфигурация компонента
- `modules/` — модули документации
  - `ROOT/` — основной модуль
  - `implementation/` — модуль реализации
  - `user-guide/` — руководство пользователя
  - другие специализированные модули
- `database.yml` — конфигурация базы данных (если применимо)

### Корневые файлы

- `antora-playbook.yml` — конфигурация сборки Antora
- `package.json` — зависимости Node.js
- `ui-files/` — пользовательский интерфейс
- `tools/` — инструменты для обработки диаграмм и данных
- `resources/` — ресурсы (шрифты, темы)

## Работа с документацией

### AsciiDoc и Antora

- Используйте AsciiDoc для написания документации
- Следуйте структуре модулей Antora
- Проверяйте корректность разметки перед коммитом
- Используйте include для переиспользования контента

### Диаграммы и схемы

- PlantUML для UML диаграмм (`.puml` файлы)
- Draw.io для архитектурных диаграмм (`.drawio` файлы)
- BPMN для бизнес-процессов (`.bpmn` файлы)
- Kroki для рендеринга диаграмм в SVG

### Структура страниц

- `pages/` — основные страницы модуля
- `partials/` — переиспользуемые фрагменты
- `images/` — изображения и диаграммы
- `attachments/` — вложения (PDF, архивы)

## Работа с компонентами

### Добавление нового компонента

1. Создайте директорию в `components/`
2. Добавьте `antora.yml` с метаданными
3. Создайте структуру модулей
4. Обновите `antora-playbook.yml`
5. Добавьте компонент в навигацию

### Редактирование существующего компонента

- Работайте в соответствующей директории компонента
- Обновляйте навигацию в `nav.adoc`
- Проверяйте ссылки между страницами
- Обновляйте диаграммы при изменении архитектуры

## Локальная разработка

### Требования

- Node.js (версия указана в `package.json`)
- Docker и Docker Compose
- Kroki сервер для рендеринга диаграмм

### Запуск

```bash
# Установка зависимостей
npm install

# Запуск Kroki сервера
docker-compose -f docker/docker-compose.yml up -d

# Сборка документации
npx antora antora-playbook.yml

# Просмотр результата
open public/index.html
```
