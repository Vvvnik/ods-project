# Develop: документация (последний блок цепочки)

После **intro** и **формата AsciiDoc** — этот файл. Он задаёт **только** смысл и структуру **тела** под `===` (common не дублируй).

## Структура тела

- **2–4 абзаца**, между ними пустая строка; в абзаце **3–4 предложения**, одна мысль.
- Есть **вложенные задачи** → после 1–2 абзацев строка **«Ключевые изменения:»**, пустая строка, список `*` (4–10 коротких пунктов; один факт — один пункт, без слияния задач).
- В `===` не дублируй ID; без «Release Note». Без второго `===` и без таблиц.
- Строка **`===`** и весь текст должны **соответствовать теме задачи из источника** (часто первая строка вида `# KEY: …` или явное название в блоке задачи): если там «разработать сервис…», не своди смысл к обобщённому «улучшение…», если это меняет суть. Допустимо сократить формулировку под лимит заголовка, **смысл и тип работ** (разработка / доработка / исправление) сохраняй.

## Содержание

- Аудитория по умолчанию **без** техподготовки: что / зачем / где в UI (если в источнике). Эпик (`ODS-6.md` и т.п.: сервис, цель) — **≥1** предложение своими словами; опирайся на **название и описание** этой задачи, чтобы не разъехаться с формулировкой в Jira.
- Факты и цифры только из «Тексты задач»; UI без имени в источнике — нейтрально.

## Вступление

- Допустимо: «Реализована возможность…», «Внесены изменения…», «Исправлено…», «Доработано…», «Оптимизировано…».

## Self-check

1. Эпик учтён, если был во входе; заголовок `===` и тезисы **не противоречат** названию/типу работы из источника.
2. При вложенных задачах есть «Ключевые изменения:» со списком.
