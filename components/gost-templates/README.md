# Шаблоны документации по ГОСТ 34

Готовый комплект технической документации для ИТ-проектов. Вы один раз вводите данные о проекте, и они автоматически подставляются во все документы — название системы, сроки, имена подписантов, реквизиты договора.

## Как устроена структура папок

Документы разделены на четыре слоя. Каждый слой отвечает за свою часть.

```
partials/
├── client/          ← данные проекта (заполняется один раз)
│   ├── _attrs.adoc      — название системы, договор, сроки
│   └── _signers.adoc    — кто утверждает и подписывает документы
│
├── common/          ← единый облик всех документов (не трогать без нужды)
│   ├── _title.adoc      — настройки форматирования
│   ├── _approval.adoc   — блок «УТВЕРЖДАЮ / СОГЛАСОВАНО»
│   ├── _signature.adoc  — таблица подписей исполнителей
│   └── _changes.adoc    — лист регистрации изменений
│
├── sections/        ← стандартные разделы, общие для всего проекта
│   ├── _terms.adoc      — термины и определения
│   ├── _intro.adoc      — введение
│   └── _references.adoc — нормативные ссылки
│
├── sources/         ← технический контент, который повторяется в нескольких документах
│   ├── architecture/    — описание архитектуры
│   ├── exchange/        — описание интеграций и обменов
│   ├── security/        — описание мер безопасности
│   └── algorithms/      — описания алгоритмов
│
└── content/         ← уникальный текст каждого конкретного документа
    ├── tz/              — разделы Технического задания
    ├── chtz/            — разделы Частного технического задания
    ├── tp-functions/    — разделы документа «Описание функций»
    └── ...              — и так для каждого документа
```

**Главный принцип:** меняете данные в `client/` — они обновляются во всех документах сразу. Меняете текст в `content/tz/` — обновляется только ТЗ.

## Кто что заполняет

### Менеджер проекта — один раз в начале проекта

**Файл:** `partials/client/_attrs.adoc`

Здесь хранятся все реквизиты проекта: название системы, номер договора, даты, шифр. Эти данные автоматически появятся на титульных листах и во всех разделах всех документов.

Что нужно заполнить:
- Название системы (`name_system`), подсистемы (`name_subsystem`), компонента (`name_component`)
- Номер и дата договора (`contract_number`) или госконтракта (`state_contract_number`)
- Шифр документации (`code_contract`)
- Плановые сроки (`start_period`, `end_period`)
- Город и год (`city`, `year`)

**Файл:** `partials/client/_signers.adoc`

Здесь указываются ФИО и должности всех, кто участвует в подписании документов: представитель заказчика, исполнитель, согласовавший. Вводится один раз и применяется ко всем документам.

### Аналитик или технический писатель — по мере написания документов

**Папка:** `partials/content/<документ>/`

Содержательная часть каждого документа. Каждый раздел — отдельный файл. Например, для ТЗ:

```
content/tz/
├── _tz_general.adoc      — Общие сведения
├── _tz_purpose.adoc      — Цели и назначение
├── _tz_object.adoc       — Характеристика объектов
├── _tz_requirements.adoc — Требования к системе
├── _tz_works.adoc        — Состав и содержание работ
├── _tz_order.adoc        — Порядок разработки
├── _tz_acceptance.adoc   — Порядок приёмки
├── _tz_docs.adoc         — Требования к документированию
└── _tz_sources.adoc      — Источники разработки
```

Разделы можно писать параллельно: один аналитик пишет требования, другой — порядок работ.

**Папка:** `partials/sections/`

Термины, введение, нормативные ссылки — обычно заполняются один раз и используются во всех документах проекта без изменений.

### Архитектор или ведущий разработчик

**Папка:** `partials/sources/`

Описание архитектуры, схемы интеграций, меры безопасности. Эти блоки написаны один раз, но включаются в несколько документов сразу (например, описание архитектуры есть и в ТЗ, и в ТП).

## Как клиент получает готовые документы

### Вариант 1 — PDF-файлы

Запустите сборку из корня проекта:

```bash
ruby tools/start.rb
```

Готовые PDF появятся в папке `modules/ROOT/attachments/`.

### Вариант 2 — HTML-сайт

```bash
npm run site
```

Сайт со всеми документами откроется в браузере. Документы можно просматривать прямо в браузере, искать по тексту, переходить по ссылкам между разделами.

### Вариант 3 — предпросмотр в редакторе (для проверки в процессе)

Откройте любой файл из папки `pages/` в VS Code и нажмите **Cmd+Option+C** (macOS) — откроется предпросмотр документа.

## Как начать новый проект

1. **Скопируйте папку `gost-templates`** в новое место или создайте новую ветку в репозитории.

2. **Заполните данные проекта** — откройте `partials/client/_attrs.adoc` и замените примеры на реальные данные вашего проекта.

3. **Заполните подписантов** — откройте `partials/client/_signers.adoc` и укажите ФИО и должности всех, кто будет подписывать документы.

4. **Заполните термины** — откройте `partials/sections/_terms.adoc` и добавьте сокращения и определения, специфичные для вашего проекта.

5. **Заполняйте разделы по очереди** — для каждого нужного документа открывайте файлы в `partials/content/<документ>/` и пишите содержательную часть. Не нужные документы можно просто не трогать.

6. **Соберите PDF** — запустите `ruby tools/start.rb` и передайте файлы заказчику.

> **Совет:** используйте готовые примеры из папки `examples/` как образцы заполнения. Там показано, как выглядит правильно заполненный файл.

## Частые вопросы

**— Я изменил название системы в одном документе, но в остальных оно не обновилось.**

Название системы должно быть в `partials/client/_attrs.adoc`, поле `:name_system:`. Если вы редактировали сам документ (в папке `pages/`), изменение затронет только его. Перенесите правку в `_attrs.adoc` — и обновятся все сразу.

---

**— Мне нужно добавить ещё одного согласовавшего на титульный лист.**

Откройте `partials/common/_approval.adoc` и добавьте строку в таблицу «СОГЛАСОВАНО». Изменение появится во всех документах.

---

**— Документ нужен с подписями исполнителей, а у меня их нет.**

Подписи появляются автоматически, если в файле документа (`pages/`) установлено `:custom_title_page: contract`. Для остальных типов оформления (`original`, `original_frame`) блок подписей не выводится — это нормально.

---

**— Я открыл файл в редакторе, а там только строки `include::`. Это нормально?**

Да. Файлы в папке `pages/` — это сборщики: они указывают, из каких кусочков состоит документ. Само содержимое находится в `partials/`. Для предпросмотра нажмите Cmd+Option+C в VS Code.

---

**— Как добавить новый документ, которого нет в шаблонах?**

1. Создайте файл в `pages/` — скопируйте любой существующий как основу.
2. Создайте папку в `partials/content/<название>/` и добавьте в неё файлы разделов.
3. Добавьте ссылку на новый документ в `nav.adoc` и `pages/index.adoc`.

---

**— Как сделать так, чтобы в документе не было титульного листа с рамкой?**

В файле документа (`pages/`) измените параметр `:custom_title_page:`:
- `original_frame` — стандартная рамка ГОСТ
- `original` — без рамки
- `contract` — оформление для договорной документации (добавляет блок подписей)

---

**— Нужно передать шаблоны заказчику, чтобы он сам заполнял. Что ему дать?**

Достаточно двух файлов из `attachments/client/`:
- `attrs-template.adoc` — шаблон с реквизитами проекта
- `signers-template.adoc` — шаблон с подписантами

Заказчик заполняет их, вы вставляете в `partials/client/` — и всё собирается автоматически.
