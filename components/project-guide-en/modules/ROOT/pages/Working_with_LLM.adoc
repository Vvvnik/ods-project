== Overview

The system uses LLM (Large Language Model) for automatic translation of database attributes. Translation to Russian and English is supported using the local Ollama model.

== System Architecture

=== Components

* **LLMClient** - client for working with Ollama;
* **TranslationUtils** - utilities for working with dictionary and log;
* **PromptLoader** - prompt loader;
* **ConfigLoader** - configuration loader;

=== File Structure

[source,text]
----
tools/
├── log/
│   └── database_translations_log.txt    # LLM translation log
├── dictionary/
│   └── database_translations.yml       # Translation dictionary
├── prompts/
│   └── database_translations.prompt    # Universal prompt
└── lib/
    ├── llm_client.rb                   # LLM client
    ├── translation_utils.rb            # Translation utilities
    └── prompt_loader.rb                # Prompt loader
----

== Configuration

=== Settings in config.yml

[source,yaml]
----
db:
  translate: "ru"                        # Translation language: "ru", "en", false
  dictionary: "tools/dictionary/database_translations.yml"
  prompt: "database_translations"
----

=== Supported Languages

* `"ru"` or `true` - translate to Russian;
* `"en"` - translate to English  ;
* `false` - disable translations;

== Work Logic

=== Translation Algorithm

1. **Preliminary collection**: Collect all database fields for translation (without generating documentation)
2. **Batch translation**: Translate all collected fields through LLM in one request
3. **Documentation generation**: Create documentation with already translated names
4. **Comment check**: If field has comment in database - use it as is
5. **Dictionary check**: Look for translation in dictionary (priority over LLM)
6. **Language check**: If translation is in different language - ignore and translate again
7. **Save**: Results are saved to dictionary and log

=== Batch Processing

The system uses "super acceleration" - instead of individual LLM requests, it collects fields in batches of 50:

**New work sequence:**
1. **Field collection**: Go through all database tables and collect fields for translation
2. **Batch translation**: Translate all fields in one LLM request
3. **Documentation generation**: Create documentation with already translated names

[source,ruby]
----
# Collecting fields for translation
MISSING_FIELDS = []

# Batch processing
def process_batch_translation(llm_client, translation_utils, translate_comments)
  batches = MISSING_FIELDS.each_slice(50).to_a
  batches.each do |batch|
    translations = llm_client.translate_batch(batch, translate_comments)
    # Save results
  end
end
----

=== Automatic Population

The dictionary is automatically populated with new translations on each run. Repeated translations are not performed.

== Prompt

=== Universal Prompt

A single prompt `database_translations.prompt` is used for all translation cases:

[source,text]
----
Translate the following database fields to <%= target_language %>:

<% fields.each_with_index do |field, index| %>
<%= index + 1 %>. <%= field %>
<% end %>

Requirements:
<% if target_language == "Russian" %>
- Translate each word exactly to Russian
- Replace underscores with spaces
- Start with capital letter
- Answer ONLY with translation, no explanations
- Don't add words "field", "attribute", "data" if they're not in original

Examples:
user_id → User ID
created_at → Created at
<% else %>
- Convert snake_case to readable words
- Replace underscores with spaces
- Start with capital letter
- Answer ONLY with translation, no explanations
- Don't add words "field", "attribute", "data" if they're not in original

Examples:
user_id → User ID
created_at → Created at
<% end %>
----

== Performance

=== Speed Comparison

* **Individual translation**: 50 fields = 50 LLM requests (~50-100 seconds);
* **Batch translation**: 50 fields = 1 LLM request (~2-5 seconds);
* **Time savings**: 45-95 seconds;

=== Caching

The system uses translation cache to avoid repeated requests:

[source,ruby]
----
TRANSLATION_CACHE = {}

def translate_field(name, comment, translate_comments, llm_client, translation_utils)
  cache_key = "#{name}_#{translate_comments}"
  return TRANSLATION_CACHE[cache_key] if TRANSLATION_CACHE.key?(cache_key)
  # ... translation logic
end
----

== Limitations

=== LLM Requirements

* Local Ollama installation;
* `gemma:latest` model or compatible;
* Server availability on `http://localhost:11434`;

=== Fallback Mechanism

When LLM is unavailable, the system uses simple conversion:

[source,ruby]
----
def create_fallback_translation(text)
  text.gsub(/([a-z])([A-Z])/, '\1 \2')
      .tr('_', ' ')
end
----

== Local Usage

The LLM system is designed for **local use** on developer machine. This provides:

* **Fast access** to Ollama without network delays;
* **Full control** over models and settings;
* **Security** - data not transmitted to external services;
* **Stability** - doesn't depend on external API availability;

=== Local Environment Requirements

1. **Installed Ollama**: Local Ollama server
2. **Loaded model**: `gemma:latest` or similar
3. **Running server**: `ollama serve` must be working
4. **Ruby environment**: All necessary gems installed

=== Adding New Functionality

==== Creating New Prompt

Create prompt file in `tools/prompts/`:

[source,erb]
----
# tools/prompts/api_documentation.prompt

Translate the following API documentation to <%= target_language %>:

<%= api_doc %>

Requirements:
- Preserve documentation structure
- Translate only descriptions, keep method names in English
- Answer in Markdown format

Translation:
----

==== Creating New Dictionary

Create YAML dictionary file:

[source,yaml]
----
# tools/dictionary/api_translations.yml

---
translations:
  get_user: Get user
  create_user: Create user
  update_user: Update user
----

==== Configuration Update

Add new section to `tools/config.yml`:

[source,yaml]
----
api:
  enabled: true
  translate: "ru"
  dictionary: "tools/dictionary/api_translations.yml"
  prompt: "api_documentation"
  log: "tools/log/api_translations_log.txt"
----

==== Creating New Script

Create script for API documentation processing:

[source,ruby]
----
# tools/scripts/api_to_adoc.rb

require_relative '../lib/config_loader'
require_relative '../lib/llm_client'
require_relative '../lib/translation_utils'

# Load configuration
config = ConfigLoader.load_config

# Initialize LLM client
llm_client = LLMClient.new(
  config.dig('ollama', 'host'),
  config.dig('ollama', 'model'),
  config.dig('api', 'prompts'),
  config.dig('api', 'prompt')
)

# Initialize translation utilities
translation_utils = TranslationUtils.new(
  config.dig('api', 'dictionary'),
  config.dig('api', 'log')
)

# Main processing logic
def translate_api_doc(api_doc, translate_comments, llm_client, translation_utils)
  # Check dictionary
  if translation_utils.has_translation?(api_doc)
    return translation_utils.get_translation(api_doc)
  end
  
  # Translate through LLM
  translation = llm_client.translate_batch([api_doc], translate_comments)
  
  # Save to dictionary
  translation_utils.add_translation(api_doc, translation[api_doc])
  
  translation[api_doc]
end

# Usage
api_doc = "Get user information"
translated = translate_api_doc(api_doc, "ru", llm_client, translation_utils)
puts translated  # "Get user information"
----

==== Integration into Main Script

Add call to new script in `tools/start.rb`:

[source,ruby]
----
# tools/start.rb

components.each do |component|
  # ... existing code ...
  
  if component['api'] && component['api']['enabled']
    system("ruby tools/scripts/api_to_adoc.rb --component #{component['name']}")
  end
end
----
