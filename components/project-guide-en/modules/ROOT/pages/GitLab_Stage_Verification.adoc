= GitLab Stage Verification

== CI/CD Pipeline Overview

The project uses GitLab CI/CD for automatic documentation build and site publication. The pipeline consists of two main stages: `build` and `deploy`.

== Build Stages

=== build_all Stage

Combined PDF and documentation site build:

**Image:** `registry.gitlab.com/vvvnik/ods-project/ruby-node-antora:1`

**Services:**

* Kroki server: `registry.gitlab.com/vvvnik/ods-project/kroki:0.28.0`

**Script:**

. PDF generation: `ruby tools/start.rb`
. Node.js dependency installation: `npm ci` or `npm install`
. Site build: `antora antora-playbook.yml`
. Artifact preparation: copying to `public/` folder

**Artifacts:** `public/` folder (valid for 3 days)

**Launch conditions:**

* On `main` branch
* When technical files change (`tools/**`, `.gitlab-ci.yml`, `modules/**`, `antora-playbook.yml`, `components/*/antora.yml`, `resources/**`)
* When `antora-*.yml` files change
* Or when previous stages complete successfully

=== pages Stage

Site publication on GitLab Pages:

**Dependencies:** `build_all`

**Script:** `echo "Deploy GitLab Pages"`

**Artifacts:** `public/` folder (no expiration)

**Launch conditions:**

* On `main` branch
* When technical files change
* Or when previous stages complete successfully

== Release Stages

=== prepare_release_notes Stage

Release notes preparation when creating tags:

**Image:** `alpine:latest`

**Script:**

. Getting commit history between tags
. Generating `dist/release-notes.adoc` file
. Formatting in AsciiDoc format

**Artifacts:** `dist/release-notes.adoc` (valid for 3 days)

**Launch conditions:** only when creating tags

=== release Stage

GitLab Release creation:

**Image:** `registry.gitlab.com/gitlab-org/release-cli:latest`

**Dependencies:** `prepare_release_notes`

**Script:**
. Creating release with notes
. Attaching `release-notes.adoc` file

**Launch conditions:** only when creating tags

== Stage Verification

=== What to Check

. **build_all** - ensure stage completed and created `public/` artifacts
. **pages** - check that site is published on GitLab Pages
. **prepare_release_notes** (for tags) - check release notes generation
. **release** (for tags) - check GitLab Release creation

=== Environment Variables

* `KROKI_SERVER_URL: "http://kroki:8000"` - Kroki server URL in CI
* `KROKI_IMAGE: "registry.gitlab.com/vvvnik/ods-project/kroki:0.28.0"` - Kroki image
* `TECHNICAL_FILES` - technical files affecting build

=== Caching

* `node_modules/` and `.npm/` cached by key `${CI_COMMIT_REF_SLUG}`
* Speeds up repeated builds

== Troubleshooting

In case of errors or incorrect operation of stages, refer to the section xref:Editing_and_Verification.adoc[Editing and Verification].

=== Common Issues

* **Kroki errors** - check Kroki service availability
* **PDF generation errors** - check configuration in `tools/config.yml`
* **Antora errors** - check `antora-playbook.yml` and Node.js dependencies
* **Artifact issues** - check access rights and file sizes
