= Docker Build and Services

== Images
Universal image is used in CI for PDF and site builds.

* **Universal Image**: registry.gitlab.com/vvvnik/ods-project/ruby-node-antora:2:
** Contains Ruby 3.2 + Node.js 20 + Asciidoctor + Antora + all necessary packages;
** Used in CI for PDF and site builds;
** Built from `docker/Dockerfile.universal`;
** All package versions are pinned for reproducible builds (gems and npm packages with exact versions).
** This includes global installs of the Antora CLI, site generators, `+@antora/lunr-extension+`, and `+@opendevise/antora-swagger-ui-extension+` – they should stay aligned with the `antora.extensions` list in `antora-playbook.yml`.
* **Kroki Service**: registry.gitlab.com/vvvnik/ods-project/kroki:0.28.0:
** Separate container for diagram rendering;
** Connected as service in CI;
** Base image: yuzutech/kroki:0.28.0.
* **Ollama Service**: registry.gitlab.com/vvvnik/ods-project/ollama:1 (optional):
** Separate container for LLM translations;
** Connected as service in CI or docker-compose;
** Base image: ollama/ollama:latest;
** Model: gemma:latest (preloaded in model image).

== Build Scripts
=== Universal Image Build

Universal image build script is used in CI for PDF and site builds.

[source,bash]
----
# Build and push to registry (default)
./docker/build-images.sh [tag]

# Build only, don't push to registry
./docker/build-images.sh [tag] --no-push

# Examples
./docker/build-images.sh 2
./docker/build-images.sh 2 --no-push
----

=== Kroki Image Build
Kroki image build script is used in CI for diagram rendering.

[source,bash]
----
# Build and push to registry (default)
./docker/build-kroki.sh [tag]

# Build only, don't push to registry
./docker/build-kroki.sh [tag] --no-push

# Examples
./docker/build-kroki.sh 0.29.0
./docker/build-kroki.sh 0.29.0 --no-push
----

[[kroki-local-port]]
==== Running Kroki with port mapping (local)

`build-kroki.sh` only **builds** (and optionally **pushes**) the image; the **host port** is set in a separate `docker run`.
Without **`-p 8000:8000`**, nothing listens on the host, and `host.docker.internal:8000` from `site` / `site-preview` in `docker-compose` cannot reach Kroki.

After `./docker/build-kroki.sh --no-push` (default local tag `0.28.0`) or after `docker pull` of the same image published for CI:

[source,bash]
----
docker rm -f ods-kroki 2>/dev/null; docker run -d --name ods-kroki -p 8000:8000 registry.gitlab.com/vvvnik/ods-project/kroki:0.28.0
----

Check: **http://localhost:8000**. In **GitLab CI** the same image is attached as the **`kroki:8000`** service–the pipeline layout stays the same; only the developer machine launch differs.

[source,bash]
----

⚠️ **Important**: Image with model is very large (10+ GB), pushing to registry may take a long time.

== Local Development
=== Architecture for Local Development

For local development, `docker-compose.yml` requires only **two services**:

* **`start`** - runs `tools/start.rb` (PDF generation and related steps);
* **`site`** - Antora site build (generates static files into `public/`).

Optional preview service:

* **`site-preview`** - builds the site and starts an HTTP server on port `8080` for browser preview.

All external services (Kroki, Ollama, PostgreSQL) run **on the host** and are accessible to containers via `host.docker.internal`:

* **Kroki** - runs on host, accessible via `host.docker.internal:8000` (configured in `antora-playbook.yml`);
* **Ollama** - runs on host, accessible via `host.docker.internal:11434` (configured in `docker-compose.yml` via `OLLAMA_HOST`);
* **PostgreSQL** (pg-demo) - runs on host, accessible via `host.docker.internal` (configured via `DB_HOST`).

This architecture allows:

* Using minimal number of containers (only `pdf` and `site`);
* Reusing services running on host;
* Easy switching between local development and CI/CD.

=== Using Ready-made Images
Using ready-made images for PDF generation and site build.

[source,bash]
----
# PDF generation
docker-compose -f docker/docker-compose.yml run --rm start

# Documentation site build
docker-compose -f docker/docker-compose.yml run --rm site

# Site preview (port 8080)
docker-compose -f docker/docker-compose.yml up site-preview
#
# Alternative via run (ports must be published):
docker-compose -f docker/docker-compose.yml run --rm --service-ports site-preview

Open the server URL from the output (Ctrl+Click). To stop the server: Ctrl+C.

# With specific component
docker-compose -f docker/docker-compose.yml run --rm start ruby tools/start.rb airport-service
----

[NOTE]
After Docker site build, Antora outputs message `Open file:///app/public/index.html`, 
but you need to open `public/index.html` in the local project directory (on the host), 
since the `/app` directory inside the container is mounted to the project root.

If you see 404 requests like `GET /_/css/~@fontsource/...` in `site-preview` (`http-server`) logs, it’s usually caused by browser/server caching.
Restart `site-preview` and do a hard refresh (Cmd+Shift+R / Ctrl+F5).

=== Service Connection Check
Before running, make sure all necessary services are running on the host:

[source,bash]
----
# Check Kroki
# Check Kroki via PlantUML rendering (this is what the project actually uses)
printf '%s\n' '@startuml' 'Alice -> Bob: test' '@enduml' | \
  curl -sS -X POST http://localhost:8000/plantuml/svg \
    -H 'Content-Type: text/plain' \
    --data-binary @- -o /dev/null -w 'HTTP=%{http_code} CT=%{content_type}\n'
# Expected output:
# HTTP=200 CT=image/svg+xml

# Check Ollama
# Ollama is optional – only check if you use LLM
curl -sS http://localhost:11434/api/version || true
# Expected output (example):
# {"version":"0.13.4"}

# Check PostgreSQL
# psql may be missing on host – check that port is reachable
nc -vz localhost 5432
# Expected output (example):
# Connection to localhost port 5432 [tcp/postgresql] succeeded!
----

=== Service Configuration for docker-compose
==== Kroki Configuration

Now `kroki-server-url` is passed to Antora as a CLI attribute:

[source,bash]
----
antora generate --attribute kroki-server-url=$KROKI_SERVER_URL antora-playbook.yml
----

So you **don't need to edit** `antora-playbook.yml` for different environments.

* Locally (docker-compose) the default `KROKI_SERVER_URL` is `http://host.docker.internal:8000`
* In CI `KROKI_SERVER_URL` is `http://kroki:8000`

===== Diagrams (PlantUML) and why they may “disappear”

In this project, PlantUML diagrams are rendered via the `asciidoctor-kroki` extension, which requires a reachable Kroki server.

There are two different modes:

* *Render “at build time” (baked SVG/PNG under `public/`)*:
Antora calls Kroki during generation and writes images to `public/**/_images/`.
In this mode diagrams will be visible in the generated HTML even if Kroki is not running when you view the site.

* *No render “at build time”*:
Antora builds pages but does not fetch diagrams from Kroki during generation.
In this mode diagrams may:
** not appear in HTML;
** appear/disappear after rebuilding because `public/` is overwritten;
** “seem” present due to stale files if you didn’t use `--clean`.

In `docker/docker-compose.yml`, the `site` service uses `kroki-fetch-diagram!`, so Kroki is *not required to build*, but diagrams are *not baked into* the build output.

If you want `docker-compose -f docker/docker-compose.yml run --rm site` to always bake diagrams:

* remove `--attribute kroki-fetch-diagram!` from the `site` command;
* make sure Kroki is reachable via `KROKI_SERVER_URL` during the build.

==== Ollama Configuration

By default, `docker/docker-compose.yml` already sets `OLLAMA_HOST` for the `start` service to point to Ollama running on the host.
Change it only if you run Ollama in Docker/CI and want to use `http://ollama:11434`.

[source,yaml]
----
# docker/docker-compose.yml
services:
  start:
    environment:
      # For docker-compose local development (Ollama on host):
      - OLLAMA_HOST=http://host.docker.internal:11434
      
      # For CI/CD (Ollama as Docker service):
      # - OLLAMA_HOST=http://ollama:11434
----

Ollama address is also configured in `tools/config.yml` via environment variable:

[source,yaml]
----
# tools/config.yml
ollama:
  enabled: true
  host: "${OLLAMA_HOST:-http://localhost:11434}"  # Configured via OLLAMA_HOST
----

**Configuration options:**

* **Local development** (Ollama on host): +
  `OLLAMA_HOST=http://localhost:11434` or omit (default value)

* **Docker Compose** (Ollama on host, containers connect): +
  `OLLAMA_HOST=http://host.docker.internal:11434`

* **CI/CD** (Ollama as Docker service):
  `OLLAMA_HOST=http://ollama:11434`

:note-caption: Important

[NOTE]
Before pushing changes to CI, make sure `OLLAMA_HOST=http://ollama:11434` is set in `docker-compose.yml`, otherwise CI build won't be able to connect to Ollama service.

== Architecture

The project uses a **universal approach** with one main image and additional services:

* **ruby-node-antora:2** – main image for all build operations;
* **kroki:0.28.0** – service for diagrams (PlantUML, Mermaid, Graphviz);
* **ollama:1** – service for LLM translations (optional);

This provides:

* Fast builds (one main image);
* Reliability (all dependencies in one place);
* Easy maintenance (modular architecture);
* Flexibility (services can be enabled/disabled as needed);
