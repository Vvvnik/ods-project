== What is ODS?
ODS (Open Documentation Standard) is an open standard and toolkit for automating the processes of creating and maintaining technical documentation in IT and other projects.

The main advantages of ODS are:

* Ability for team collaboration with versioning and change control;
* Automatic generation of documentation from various sources;
* Conversion of diagrams (BPMN, Draw.io, PlantUML) into documents;
* Documenting APIs and databases;
* Creation of PDF documents and HTML sites;
* Integration with CI/CD (GitLab CI).

:tip-caption: Note:

[TIP]
ODS is not an official standard and does not replace GOST or ISO. It is a technical approach to documentation management, based on versioning, templates, and automation.

The project aims to become a template for implementing the "Docs as Code" approach in an organization and ensuring the automation of documentation processes.

Using ODS, you get:

. 📄 Documentation that is always up-to-date and reflects the actual state of the project.
. 🤝 The ability for team collaboration with versioning and change control.
. 🔄 An automated process for building documentation into a ready-made website or a set of PDF documents.

== Who is it for?
ODS is useful for:

* Developers who need to automate documentation;
* Agile and DevOps teams;
* Projects with requirements for high-quality technical documentation;
* Organizations implementing documentation standards.

This guide describes the main principles of ODS, the project architecture, component structure, build and publication tools, and examples of various document types. The guide contains all the necessary information to get started with the ODS project.

=== Key Principles of ODS
The key principles of ODS are:

* 🧩 Modularity — documentation is broken down into independent components;
* 📁 Integration — support for various data sources (API, DB, diagrams, BPMN, UML, Draw.io, PlantUML);
* 🤝 Collaboration — convenient team collaboration on documentation;
* 📅 Versioning — full change control via Git;
* 🔄 Automation — generation of documentation from source files;
* 📚 Standardization — unified documentation formats and structures.

=== Technologies Used
The project is built on the following technologies:

* link:https://antora.org/[Antora] – static site generator;
* link:https://docs.asciidoctor.org/[Asciidoctor] – AsciiDoc processor;
* link:https://developer.mozilla.org/en-US/docs/Web/JavaScript[JavaScript] – programming language for creating interactive elements and automation;
* link:https://www.ruby-lang.org/[Ruby] with the link:https://github.com/prawnpdf/prawn[Prawn] library – for generating PDF documents and automating document management processes;

== Project Architecture
For practical application of the standard, a project environment has been created that includes:

* a ready-made documentation structure;
* examples with source file templates;
* build and publication tools;
* examples of various document types on website pages and PDF documents.

The project is hosted on GitLab and is available at: link:https://gitlab.com/vvvnik/ods-project[ODS-Project].

=== Documentation Components

Each result in the components/ folder represents a separate part of the documentation:

. *airport-service/* – airport service documentation component. Contains examples of database documentation with automatic generation of ERD diagrams and DB schemas.

. *data-processing-engine/* – data processing engine documentation component. Includes hardware-complex and user-guide modules with examples of documenting business processes, BPMN, and UML diagrams.

. *information-system/* – information system documentation component. Contains ed (operational documentation), oed (pilot operation), trd (technical specification) modules with examples of project and operational documentation according to GOST.

. *project-guide/* – project and documentation guide component (this guide). Contains a complete description of the ODS system architecture, setup, and usage.

. *toys-service/* – toy service documentation component. Provides examples of automatic API documentation generation from OpenAPI specifications with UML diagrams.

More about the project architecture and component structure can be found in the section xref:Architecture_and_System_Composition.adoc[Architecture and System Composition].

More about the repository structure and its components can be found in the section xref:Repository_Preparation.adoc[Repository Preparation].

=== Build Tools

The *tools/* folder contains all necessary tools for automation:

* *scripts/* – Ruby scripts for documentation generation;
* *lib/* – libraries and modules;
* *config.yml* – main configuration;
* *start.rb* – main launch script.
