== Environment Variables

The following variables are used in CI/CD:

* `KROKI_SERVER_URL: "http://kroki:8000"` – Kroki service URL for diagram generation;
* `KROKI_IMAGE: "registry.gitlab.com/vvvnik/ods-project/kroki:0.28.0"` – Kroki service image;
* `GIT_DEPTH: "20"` – Git repository cloning depth;
* `TECHNICAL_FILES` – pattern of files affecting content generation;

=== Note about diagrams (Kroki)

To render PlantUML/other diagrams in HTML during CI builds, the pipeline uses the Kroki service (`alias: kroki`).
If Kroki is not reachable, Antora may finish with warnings and diagrams may not be included in the build output.

If you want the build to be “strict” (fail on rendering warnings):

[source,bash]
----
antora generate --log-failure-level warn --attribute kroki-server-url=$KROKI_SERVER_URL antora-playbook.yml
----

== Validating CI configuration locally (glab)

https://gitlab.com/gitlab-org/cli[**GitLab CLI (glab)**] lints `.gitlab-ci.yml` through the GitLab API–useful before you push.

[source,bash]
----
brew install glab
glab auth login
glab ci lint
----

* `glab auth login` – sign in to `gitlab.com` (or your GitLab instance); if you interrupt the interactive flow, run the command again.
* Success: the output includes `CI/CD YAML is valid!`.

== Detailed Stage Descriptions

=== build_all
Main documentation build stage with sequential command execution:

. **Image**: `registry.gitlab.com/vvvnik/ods-project/ruby-node-antora:2`
. **Services**: Kroki (`registry.gitlab.com/vvvnik/ods-project/kroki:0.28.0`) for diagram generation
. **Cache**: `node_modules/` and `.npm/` to speed up builds (key: `${CI_COMMIT_REF_SLUG}`)
. **Execution sequence**:
.. Ruby and Node.js version check
.. PDF document generation via `ruby tools/start.rb`
.. Node.js dependency installation (`npm ci` or `npm install`)
.. Site generation via `antora generate --attribute kroki-server-url=$KROKI_SERVER_URL antora-playbook.yml`
.. Result copying: `cp -a build/site/. public/` (if public/ doesn't exist)
. **Artifacts**: `public/` folder (expires in 3 days)
. **Triggers**:
.. Changes in technical files (`tools/**`, `antora-playbook.yml`, `components/*/antora.yml`, `resources/**`)
.. Every push to main (if no changes in technical files)
.. NOT executed when creating tags
.. Merge Request events

=== pages
Site publication stage on GitLab Pages:

. **Dependencies**: requires `build_all` completion
. **Stage**: `deploy`
. **Action**: deploy artifacts to GitLab Pages
. **Script**: `echo "Deploy GitLab Pages"` (symbolic command)
. **Result**: documentation site available online
. **Artifacts**: `public/` folder (doesn't expire)
. **Triggers**: same as `build_all`, but NOT executed when creating tags

=== prepare_release_notes
Release notes preparation stage (only when creating tags):

. **Trigger**: tag creation in repository
. **Image**: `alpine:latest`
. **Stage**: `deploy`
. **Preparation**:
.. Git installation (`apk add --no-cache git`)
.. Safe directory setup
.. Getting all tags from repository
.. Unpacking shallow repository (if necessary)
. **Generation logic**:
.. Determining previous tag (3 search strategies: tag parent, previous by version, previous by date)
.. Creating commit range between tags
.. Generating `dist/release-notes.adoc` file with commits
. **Result**: `dist/release-notes.adoc` file
. **Artifacts**: `dist/release-notes.adoc` (expires in 3 days)

=== release
Official release creation stage:

. **Dependencies**: requires `prepare_release_notes` completion
. **Image**: `registry.gitlab.com/gitlab-org/release-cli:latest`
. **Stage**: `deploy`
. **Action**: create GitLab Release with notes
. **Process**:
.. Reading notes from `dist/release-notes.adoc`
.. Creating release with name and description
.. Adding link to notes file as asset
. **Result**: official release with change descriptions
. **Assets**: link to `release-notes.adoc` from `prepare_release_notes` artifacts

== Dependencies
Dependencies between build stages:

* pages depends on build_all;
* prepare_release_notes executes only when creating tags;
* release depends on prepare_release_notes;

== Change Tracking
Add to changes:

* tools/ – generation scripts and configuration;
* components/*/modules/ – documentation content;
* antora-playbook.yml – site build settings;
* resources/ – PDF themes and fonts;

== Working with Media Files in GitLab Package Registry

To host videos and other media files in documentation, you can use GitLab Package Registry. This allows storing large files separately from the repository and referencing them in documentation.

=== Uploading Videos to Package Registry

To upload a video to GitLab Package Registry, use the GitLab API:

[source,bash]
----
curl --header "PRIVATE-TOKEN: <your_token>" \
     --upload-file video.mov \
     "https://gitlab.com/api/v4/projects/<project_id>/packages/generic/videos/<version>/<filename>"
----

**Parameters:**

* `PRIVATE-TOKEN` – GitLab personal access token (created in Settings → Access Tokens);
* `project_id` – Project ID (found in Settings → General, or use `namespace%2Fproject-name`);
* `videos` – Package name (you can use any name);
* `<version>` – Package version (e.g., `1.0.0`);
* `<filename>` – File name to upload;

**Example:**

[source,bash]
----
curl --header "PRIVATE-TOKEN: xxxxxxxxxxxxxxxxxxxx" \
     --upload-file video.mov \
     "https://gitlab.com/api/v4/projects/vvvnik%2Fods-project/packages/generic/videos/1.0.0/video.mov"
----

:tip-caption: Tip

[TIP]
For security, store the token in environment variables or use GitLab CI/CD variables. In the command, you can use `$GITLAB_TOKEN` instead of directly specifying the token.

=== Using Videos in Documentation

After uploading a video to Package Registry, get a direct link to the file through the GitLab web interface:

. Go to the project's Package Registry: `Packages & Registries → Package Registry`
. Find the uploaded file and copy the download link

In AsciiDoc, use the `video::` directive to embed videos:

[source,asciidoc]
----
video::https://gitlab.com/vvvnik/ods-project/-/package_files/253856660/download[width=100%]

Download the link:https://gitlab.com/vvvnik/ods-project/-/package_files/253856660/download[introductory video] of the project.
----

**Parameters:**

* `width=100%` – Video width (can be specified in pixels or percentages);
* Download link – Used for direct link to the file;

:warning-caption: Important

[WARNING]
The file link in Package Registry contains a file ID that can only be obtained through the GitLab web interface after uploading the file.
