= User Guide

== Creating a New Documentation Component

This guide contains step-by-step instructions for creating a new documentation component in the ODS system. As an example, we will create a component called `my-new-project`.

=== Step 1: Creating Folder Structure

Create the basic component structure:

[source,bash]
----
mkdir -p components/my-new-project/modules/ROOT/{pages,partials,attachments,images,examples}
----

The structure should look like this:

[source,text]
----
components/my-new-project/
└── modules/
    └── ROOT/
        ├── pages/           # AsciiDoc documentation files
        ├── partials/        # AsciiDoc partial files  
        ├── attachments/     # Generated PDF files
        ├── images/          # Images and diagrams
        └── examples/        # Source files for generation
----

=== Step 3: Configuration Setup

==== Adding to config.yml

Add the new component to `tools/config.yml`:

[source,yaml]
----
components:
  - name: my-new-project
    <<: *defaults
    drawio:
      enabled: true
    pdf:
      enabled: true
----

For more details on config.yml setup, see xref:Config_YML_Setup.adoc[Config.yml Setup].

==== Adding to antora-playbook.yml

Add the content source to `antora-playbook.yml`:

[source,yaml]
----
content:
  sources:
    - url: .
      branches: HEAD
      worktrees: true
      start_path: components/my-new-project
----

==== UI and Styles Setup

To configure the user interface and styles, use the `ui` section in `antora-playbook.yml`:

[source,yaml]
----
ui:
  bundle:
    url: ./ui-files/ui-bundle.zip
    snapshot: true
  supplemental_files: ./ui-files/ui-bundle-style
----

Where:

* `bundle.url` – path to the main UI bundle (archive with themes);
* `bundle.snapshot: true` – use local version without checking for updates;
* `supplemental_files` – path to additional style files for customizing the site appearance.

Files in `supplemental_files` override styles from the main bundle, allowing you to configure:

* Site color scheme;
* Fonts and typography;
* Layout and spacing;
* Additional CSS styles.

=== Step 4: Using Templates

The system provides ready-made templates in the `templates/` folder:

[source,text]
----
templates/
├── diagrams/               # Diagram examples
│   ├── puml/              # PlantUML diagram examples
│   └── drawio/            # Draw.io diagram examples
├── glossary/               # Dictionaries and terms  
├── snippets/               # Code fragments
└── templates_doc/modules/  # Document templates
    ├── oed/                # Trial operation documentation
    ├── ROOT/               # Main templates
    └── trd/                # Technical documentation
----

Example of copying a template:

[source,bash]
----
# Copying technical specification template
cp templates/templates_doc/modules/trd/pages/Частное_техническое_задание.adoc \
   components/my-new-project/modules/ROOT/pages/technical-spec.adoc
----

For detailed description of all templates, diagram examples, and usage recommendations, see xref:Templates_and_Examples.adoc[Templates and Examples].

=== Step 5: Generation Setup

==== PDF Attributes

For correct PDF generation, add attributes at the beginning of files:

[source,adoc]
----
:doctype: book
:custom_title_page: original      # Title page type
:custom_other_page: none         # Regular page type
----

Available types:

* `original` – standard title page;
* `contract` – title page for contracts;
* `original_frame` – title page with frames;
* `none` – without title page.

For more details, see xref:Page_Theme_Setup.adoc[Page Theme Setup].

==== Diagrams

To include diagrams, create files in `examples/`:

[source,text]
----
components/my-new-project/modules/ROOT/examples/
├── drawio/                   # Draw.io diagrams
│   └── system-architecture.drawio
├── bpmn/                     # BPMN diagrams  
│   └── business-process.bpmn
└── plantuml/                 # PlantUML diagrams
    └── class-diagram.puml
----

=== Step 6: Running Generation

==== Local Generation

Run generation for all components:

[source,bash]
----
ruby tools/start.rb
----

For more details on the script's operation, see xref:Start_RB_Script.adoc[Start.rb Script].

==== Checking Results

After generation, check the created files:

[source,bash]
----
# Check PDF files
ls -la components/my-new-project/modules/ROOT/attachments/

# Check web version
antora antora-playbook.yml
----

The result will be in the `public/my-new-project/1/` folder.
