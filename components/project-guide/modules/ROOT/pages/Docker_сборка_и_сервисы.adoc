= Docker: сборка и сервисы

== Образы

* **Универсальный образ**: registry.gitlab.com/vvvnik/ods-project/ruby-node-antora:2:
** Содержит Ruby 3.2 + Node.js 20 + Asciidoctor + Antora + все необходимые пакеты;
** Используется в CI для сборки PDF и сайта;
** Собирается из `docker/Dockerfile.universal`;
** Все версии пакетов зафиксированы для воспроизводимости сборок (gems и npm пакеты с точными версиями).
* **Kroki сервис**: registry.gitlab.com/vvvnik/ods-project/kroki:0.28.0:
** Отдельный контейнер для рендеринга диаграмм;
** Подключается как сервис в CI;
** Базовый образ: yuzutech/kroki:0.28.0.
* **Ollama сервис**: registry.gitlab.com/vvvnik/ods-project/ollama:1 (опционально):
** Отдельный контейнер для LLM переводов;
** Подключается как сервис в CI или docker-compose;
** Базовый образ: ollama/ollama:latest;
** Модель: gemma:latest (предзагружена в образе с моделью).

== Скрипты сборки
=== Сборка универсального образа

[source,bash]
----
# Сборка и отправка в реестр (по умолчанию)
./docker/build-images.sh [tag]

# Только сборка без отправки в реестр
./docker/build-images.sh [tag] --no-push

# Примеры
./docker/build-images.sh 2
./docker/build-images.sh 2 --no-push
----

=== Сборка Kroki образа

[source,bash]
----
# Сборка и отправка в реестр (по умолчанию)
./docker/build-kroki.sh [tag]

# Только сборка без отправки в реестр
./docker/build-kroki.sh [tag] --no-push

# Примеры
./docker/build-kroki.sh 0.29.0
./docker/build-kroki.sh 0.29.0 --no-push

=== Сборка Ollama образа
==== Базовый образ (без модели)

Модель загружается при запуске контейнера:

[source,bash]
----
# Сборка и отправка в реестр (по умолчанию)
./docker/build-ollama.sh [tag]

# Только сборка без отправки в реестр
./docker/build-ollama.sh [tag] --no-push

# Примеры
./docker/build-ollama.sh 1
./docker/build-ollama.sh 1 --no-push
----

==== Образ с предзагруженной моделью

Модель загружается во время сборки образа (размер образа 10+ GB):

[source,bash]
----
# Сборка и отправка в реестр (по умолчанию)
./docker/build-ollama-with-model.sh [tag] [model]

# Только сборка без отправки в реестр
./docker/build-ollama-with-model.sh [tag] [model] --no-push

# Примеры
./docker/build-ollama-with-model.sh 1 gemma:latest
./docker/build-ollama-with-model.sh 1 gemma:latest --no-push
----

⚠️ **Важно**: Образ с моделью очень большой (10+ GB), загрузка в реестр может занять много времени.

== Локальная разработка

=== Архитектура для локальной разработки

Для локальной разработки в `docker-compose.yml` достаточно **двух сервисов**:

* **`pdf`** - генерация PDF документов;
* **`site`** - сборка сайта с Antora.

Все внешние сервисы (Kroki, Ollama, PostgreSQL) работают **на хосте** и доступны контейнерам через `host.docker.internal`:

* **Kroki** - запускается на хосте, доступен через `host.docker.internal:8000` (настроено в `antora-playbook.yml`);
* **Ollama** - запускается на хосте, доступен через `host.docker.internal:11434` (настроено в `docker-compose.yml` через `OLLAMA_HOST`);
* **PostgreSQL** (pg-demo) - работает на хосте, доступен через `host.docker.internal` (настроено через `DB_HOST`).

Такая архитектура позволяет:

* Использовать минимальное количество контейнеров (только `pdf` и `site`);
* Переиспользовать сервисы, запущенные на хосте;
* Легко переключаться между локальной разработкой и CI/CD.

=== Использование готовых образов

[source,bash]
----
# Генерация PDF
docker-compose -f docker/docker-compose.yml run --rm pdf

# Сборка сайта документации
docker-compose -f docker/docker-compose.yml run --rm site

# С конкретным компонентом
docker-compose -f docker/docker-compose.yml run --rm pdf ruby tools/start.rb airport-service
----

:note-caption: Важно

[NOTE]
После Docker сборки сайта Antora выводит сообщение `Open file:///app/public/index.html`, 
но файл нужно открывать в `public/index.html` проекта локальной сборки (на хосте), 
так как директория `/app` внутри контейнера монтируется в корень проекта.

=== Проверка подключения к сервисам

Перед запуском убедитесь, что все необходимые сервисы запущены на хосте:

[source,bash]
----
# Проверка Kroki
# Проверяем Kroki рендером PlantUML (это то, что реально нужно проекту)
printf '%s\n' '@startuml' 'Alice -> Bob: test' '@enduml' | \
  curl -sS -X POST http://localhost:8000/plantuml/svg \
    -H 'Content-Type: text/plain' \
    --data-binary @- -o /dev/null -w 'HTTP=%{http_code} CT=%{content_type}\n'
# Ожидаемый ответ:
# HTTP=200 CT=image/svg+xml

# Проверка Ollama
# Ollama опциональна — проверяйте только если используете LLM
curl -sS http://localhost:11434/api/version || true
# Ожидаемый ответ (пример):
# {"version":"0.13.4"}

# Проверка PostgreSQL
# psql может быть не установлен на хосте — проверим, что порт доступен
nc -vz localhost 5432
# Ожидаемый ответ (пример):
# Connection to localhost port 5432 [tcp/postgresql] succeeded!
----

=== Настройка сервисов для docker-compose
==== Настройка Kroki

При использовании `docker-compose -f docker/docker-compose.yml run --rm site` необходимо настроить `kroki-server-url` в `antora-playbook.yml`:

[source,yaml]
----
# Для docker-compose локальной разработки:
kroki-server-url: http://host.docker.internal:8000

# Перед отправкой в CI замените на:
# kroki-server-url: http://kroki:8000 # for CI
----

:note-caption: Важно

[NOTE]
Перед отправкой изменений в CI убедитесь, что в `antora-playbook.yml` установлено `kroki-server-url: http://kroki:8000`, иначе сборка в CI не сможет подключиться к Kroki сервису.

==== Настройка Ollama

При использовании `docker-compose -f docker/docker-compose.yml run --rm pdf` с LLM необходимо настроить `OLLAMA_HOST` в `docker-compose.yml`:

[source,yaml]
----
# docker/docker-compose.yml
services:
  pdf:
    environment:
      # Для docker-compose локальной разработки (Ollama на хосте):
      - OLLAMA_HOST=http://host.docker.internal:11434
      
      # Для CI/CD (Ollama как сервис в Docker):
      # - OLLAMA_HOST=http://ollama:11434
----

Адрес Ollama также настраивается в `tools/config.yml` через переменную окружения:

[source,yaml]
----
# tools/config.yml
ollama:
  enabled: true
  host: "${OLLAMA_HOST:-http://localhost:11434}"  # Настраивается через OLLAMA_HOST
----

**Варианты настройки:**

* **Локальная разработка** (Ollama на хосте): +
  `OLLAMA_HOST=http://localhost:11434` или не указывать (значение по умолчанию)

* **Docker Compose** (Ollama на хосте, контейнеры подключаются): +
  `OLLAMA_HOST=http://host.docker.internal:11434`

* **CI/CD** (Ollama как сервис в Docker):
  `OLLAMA_HOST=http://ollama:11434`

:note-caption: Важно

[NOTE]
Перед отправкой изменений в CI убедитесь, что в `docker-compose.yml` установлено `OLLAMA_HOST=http://ollama:11434`, иначе сборка в CI не сможет подключиться к Ollama сервису.

== Архитектура

Проект использует **универсальный подход** с одним основным образом и дополнительными сервисами:

* **ruby-node-antora:2** – основной образ для всех операций сборки;
* **kroki:0.28.0** – сервис для диаграмм (PlantUML, Mermaid, Graphviz);
* **ollama:1** – сервис для LLM переводов (опционально);

Это обеспечивает:

* Быструю сборку (один основной образ);
* Надежность (все зависимости в одном месте);
* Простоту поддержки (модульная архитектура);
* Гибкость (сервисы можно включать/отключать по необходимости);
