== Что такое ODS?
ODS (Open Documentation Standard) — открытый стандарт и инструментарий для автоматизации процессов создания и поддержки технической документации в ИТ и других проектах. 

Основными преимуществами ODS являются:

* Возможность совместной работы команды с версионностью и контролем изменений;
* Автоматическая генерация документации из различных источников;
* Конвертация диаграмм (BPMN, Draw.io, PlantUML) в документы;
* Документирование API и баз данных;
* Создание PDF-документов и HTML-сайтов;
* Интеграция с CI/CD (GitLab CI).

:tip-caption: Примечание:

[TIP]
ODS не является официальным стандартом и не заменяет ГОСТ или ISO. Это технический подход к ведению документации, основанный на версионности, шаблонах и автоматизации. 

Проект призван стать шаблоном к реализации подхода "Docs as Code" в организации и обеспечения автоматизации процессов документирования.  

Используя ODS, вы получаете:

. 📄 Документацию, которая всегда актуальна и отражает реальное состояние проекта.
. 🤝 Возможность совместной работы команды с версионностью и контролем изменений.
. 🔄 Автоматизированный процесс сборки документации в готовый сайт или комплект pdf документов.

== Для кого предназначен
ODS полезен для:

* Разработчиков, которым необходимо автоматизировать документирование;
* Agile и DevOps команд;
* Проектов с требованиями к качественной технической документации;
* Организаций, внедряющих стандарты документирования.

В данном руководстве описаны основные принципы ODS, архитектура проекта, структура компонентов, инструменты сборки и публикации, а также примеры различных типов документов. Руководство содержит в себе все необходимые сведения для начала работы с проектом ODS.

=== Основные принципы ODS
Основными принципами ODS являются:


* 🧩 Модульность — документация разбита на независимые компоненты.

* 📁 Интеграция — поддержка различных источников данных (API, БД, диаграммы, BPMN, UML, Draw.io, PlantUML).

* 🤝 Коллаборация — удобная совместная работа команды над документацией.

* 📅 Версионирование — полный контроль изменений через Git.

* 🔄 Автоматизация — генерация документации из исходных файлов.

* 📚 Стандартизация — единые форматы и структуры документации.

=== Используемые технологии
Проект построен на основе следующих технологий:

* link:https://antora.org/[Antora] – генератор статических сайтов;
* link:https://docs.asciidoctor.org/[Asciidoctor] – процессор AsciiDoc;
* link:https://developer.mozilla.org/en-US/docs/Web/JavaScript[JavaScript] – язык программирования для создания интерактивных элементов и автоматизации;
* link:https://www.ruby-lang.org/[Ruby] с библиотекой link:https://github.com/prawnpdf/prawn[Prawn] – для генерации PDF документов и автоматизации процессов документооборота;

== Архитектура проекта
Для практического применения стандарта создана проектная среда включающая:

Проект размещен на GitLab и доступен по ссылке: link:https://gitlab.com/vvvnik/ods-project[ODS-Project].

=== Компоненты документации

Каждый результат в папке components/ представляет собой отдельную часть документации:

. *airport-service/* – компонент документации сервиса аэропорта. Содержит примеры документирования баз данных с автоматической генерацией ERD диаграмм и схем БД.

. *data-processing-engine/* – компонент документации движка обработки данных. Включает модули hardware-complex и user-guide с примерами документирования бизнес-процессов, BPMN и UML диаграмм.

. *information-system/* – компонент документации информационной системы. Содержит модули ed (эксплуатационная документация), oed (опытная эксплуатация), trd (техническое задание) с примерами проектной и эксплуатационной документации согласно ГОСТ.

. *project-guide/* – компонент руководства по проекту и документации (данное руководство). Содержит полное описание архитектуры, настройки и использования системы ODS.

. *toys-service/* – компонент документации сервиса игрушек. Представляет примеры автоматической генерации API документации из OpenAPI спецификаций с UML диаграммами.

Подробнее об архитектуре проекта и структуре компонентов можно узнать в разделе xref:Архитектура_и_состав_системы.adoc[Архитектура и состав системы].

Подробнее о структуре репозитория и его компонентах можно узнать в разделе xref:Подготовка_репозитория.adoc[Подготовка репозитория].

=== Инструменты сборки

Папка *tools/* содержит все необходимые инструменты для автоматизации:

* *scripts/* – Ruby скрипты для генерации документации;
* *lib/* – библиотеки и модули;
* *config.yml* – основная конфигурация;
* *start.rb* – главный скрипт запуска.
