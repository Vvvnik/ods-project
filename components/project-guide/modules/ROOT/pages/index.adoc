== Что такое ODS?

ODS (Open Documentation Standard) — это открытый стандарт документирования, который обеспечивает единообразный подход к созданию, структурированию и генерации технической документации.

:tip-caption: Предупреждение

[TIP]
ODS не является официальным стандартом и не заменяет ГОСТ или ISO. Это технический подход к ведению документации, основанный на версионности, шаблонах и автоматизации. 

Проект призван стать шаблоном к реализации подхода "Docs as Code" в организации и обеспечения автоматизации процессов создания и поддержки технической документации в ИТ и других проектах.  

Используя ODS, вы получаете:

. Документацию, которая всегда актуальна и отражает реальное состояние проекта.
. Возможность совместной работы команды с версионностью и контролем изменений.
. Автоматизированный процесс сборки документации в готовый сайт или комплект pdf документов. 

=== Основные принципы ODS
Основными принципами ODS являются:

* Модульность — документация разбита на независимые компоненты;
* Интеграция — поддержка различных источников данных (API, БД, диаграммы);
* Коллаборация — удобная совместная работа команды над документацией;
* Версионирование — полный контроль изменений через Git.
* Автоматизация — генерация документации из исходных файлов;
* Стандартизация — единые форматы и структуры документации.

=== Используемые технологии
Проект построен на основе следующих технологий:

* link:https://antora.org/[Antora] – генератор статических сайтов;
* link:https://docs.asciidoctor.org/[Asciidoctor] - процессор AsciiDoc;
* link:https://developer.mozilla.org/en-US/docs/Web/JavaScript[JavaScript] – язык программирования для создания интерактивных элементов и автоматизации;
* link:https://www.ruby-lang.org/[Ruby] с библиотекой link:https://github.com/prawnpdf/prawn[Prawn] – для генерации PDF документов и автоматизации процессов документооборота;

== Архитектура проекта
Для практического применения стандарта создана проектная среда включающая:

=== Компоненты документации

Каждый результат в папке components/ представляет собой отдельную часть документации:

. *airport-service/* - компонент документации сервиса аэропорта. Представляет из себя примеры документирования баз данных (БД) с примерами автоматической генерацией схем БД.
. *data-processing-engine/* - компонент документации движка обработки данных. Представляет из себя примеры документирования бизнес-процессов с примерами автоматической генерацией BPMN и UML диаграмм бизнес-процессов.
. *information-system/* - компонент документации информационной системы. Представляет из себя примеры проектной и эксплуатационной документации на информационную систему с примерами автоматической генерацией UML  и Draw.io диаграмм архитектуры системы;
. *project-guide/* - компонент руководства по проекту и документации (данное руководство);
. *toys-service/* - компонент документации сервиса игрушек. Представляет из себя примеры представления автоматической генерации документов API с примерами автоматической генерацией UML диаграмм.

Подробнее об архитектуре проекта и структуре компонентов можно узнать в разделе xref:Архитектура_и_состав_системы.adoc[Архитектура и состав системы ODS].

Подробнее о структуре репозитория и его компонентах можно узнать в разделе xref:Подготовка_репозитория.adoc[Подготовка репозитория].

=== Инструменты сборки

Папка *tools/* содержит все необходимые инструменты для автоматизации:

* *scripts/* - Ruby скрипты для генерации документации;
* *lib/* - библиотеки и модули;
* *config.yml* - основная конфигурация;
* *start.rb* - главный скрипт запуска.

== Быстрый старт

=== Установка зависимостей

Для работы с системой ODS необходимо установить:

* Ruby 3.2+ и gems для Asciidoctor PDF, операций с файлами и генерации PDF документов;
* Node.js 20+ для генерации диаграмм и сайта с помощью Antora;
* Docker и Docker Compose для локальной разработки и CI/CD;
* Kroki сервис в Docker контейнере для генерации диаграмм.

Для генерации диаграмм используются:

* Kroki сервис в Docker контейнере для генерации PlantUML и Graphviz диаграмм;
* Puppeteer для генерации BPMN диаграмм из XML файлов;
* Draw.io CLI для генерации SVG диаграмм из .drawio файлов.

=== Конфигурация
Основные файлы конфигурации:

* tools/config.yml - настройки генерации диаграмм, API, БД и PDF
* antora-playbook.yml - настройки сборки сайта с Antora

Перед первым запуском необходимо проверить настройки в конфигурационных файлах.
Подробнее о конфигурации можно узнать в разделе xref:Настроика_config_yml.adoc[Настройка config.yml]. Подробнее о настройке сайта с помощью Antora можно узнать в разделе xref:https://docs.antora.org/antora/latest/playbook/[Antora Playbook Introduction].

=== Первый запуск
Для первого запуска необходимо выполнить следующие действия:

. Установите Docker и Docker Compose;
. Запустите Kroki сервис в Docker контейнере для генерации диаграмм;
. Запустите сборку документации через Docker контейнер с Ruby и Node.js;
. Соберите сайт с помощью Antora;
. Откройте сгенерированный сайт в браузере.

=== Сборка документации
Сборка документации производится с помощью скрипта start.rb:

В случае проблем или ошибок:

* Проверьте логи выполнения в терминале;
* Убедитесь, что все зависимости установлены;
* Проверьте права доступа к файлам;

Возможными проблемами при сборке документациимогут быть:

* Конфликты портов или пересекающиеся в настройках подключения к БД и swagger;
* Отсутствующие зависимости Ruby или Node.js;
* Ошибки в config файлах конфигурации.

Для правок, отладки и проверки обратитесь к разделу xref:Правка_и_проверка.adoc[Правка и проверка].
