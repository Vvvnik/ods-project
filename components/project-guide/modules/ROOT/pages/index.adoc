== Что такое ODS?

ODS (Open Documentation Standard) — это стандарт открытой документации, который обеспечивает единообразный подход к созданию, структурированию и генерации технической документации для проектов.

Не является официальным стандартом. Проект призван стать шаблоном к реализации подхода "Docs as Code" в организации и обеспечения автоматизации процессов создания и поддержки технической документации в ИТ и других проектах.

=== Основные принципы ODS
Основными принципами ODS являются:

* Модульность — документация разбита на независимые компоненты;
* Интеграция — поддержка различных источников данных (API, БД, диаграммы);
* Автоматизация — генерация документации из исходных файлов;
* Стандартизация — единые форматы и структуры.

=== Компоненты документации

Каждый результат в папке components/ представляет собой отдельную часть документации:

* airport-service/ - документация сервиса аэропорта;
* data-processing-engine/ - документация движка обработки данных;
* information-system/ - документация информационной системы;
* project-guide/ - руководство по проекту и документации;
* toys-service/ - документация сервиса игрушек.

=== Инструменты сборки

Папка tools/ содержит все необходимые инструменты для автоматизации:

* scripts/ - Ruby скрипты для генерации документации;
* lib/ - библиотеки и модули;
* config.yml - основная конфигурация;
* start.rb - главный скрипт запуска.

== Быстрый старт

=== Установка зависимостей

Для работы с системой ODS необходимо установить:

* Ruby 3.0+ и gem dependencies;
* Docker и Docker Compose;
* Node.js 16+ для Kroki сервиса.

=== Первый запуск
Для первого запуска необходимо выполнить следующие действия:

. Настройте окружение;
. Настройте Git hooks (опционально);
. Запустите локальный Kroki сервис;
. Соберите документацию;
. Откройте сайт.

=== Публикация

Документация автоматически публикуется через CI/CD пайплайн GitLab при пуше в основную ветку.

== Основные команды

=== Сборка документации
Сборка документации производится с помощью скрипта start.rb:

В случае проблем или ошибок:

* Проверьте логи выполнения в терминале;
* Убедитесь, что все зависимости установлены;
* Проверьте права доступа к файлам;
* Для вопросов создавайте issue в GitLab.

Ожидаемыми проблемами могут быть:

* Конфликты портов или пересекающиеся порты;
* Отсутствующие зависимости Ruby или Node.js;
* Ошибки в YAML конфигурации, файл config.yml;
* Ошибки в конвертерах типов страниц, файл config_type_page.yml;
* Ошибки в конвертерах диаграмм;
* Ошибки в конвертерах API, файл sources.yml;
* Ошибки в конвертерах БД, файл database.yml;
* Ошибки в конвертерах PDF.

Для правок, отладки и проверки обратитесь к разделу xref:Правка_и_проверка.adoc[Правка и проверка].
