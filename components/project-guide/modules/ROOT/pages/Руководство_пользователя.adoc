= Руководство пользователя ODS

== Создание первого проекта

Данный раздел содержит пошаговое руководство по созданию нового компонента документации в системе ODS. В качестве примера создадим компонент first-project (Мой первый проект) по аналогии с существующим компонентом information-system.

=== Шаг 1: Создание структуры компонента

Создайте папку компонента в директории components/:

[source,bash]
----
mkdir -p components/first-project/modules/ROOT/pages
mkdir -p components/first-project/modules/ROOT/partials
mkdir -p components/first-project/modules/ROOT/attachments
mkdir -p components/first-project/modules/ROOT/images
mkdir -p components/first-project/modules/ROOT/examples
----

Структура компонента должна выглядеть следующим образом:

[source,text]
----
components/first-project/
├── modules/
│   └── ROOT/
│       ├── pages/           # AsciiDoc файлы документации
│       ├── partials/        # Части AsciiDoc файлов
│       ├── attachments/     # Сгенерированные PDF файлы
│       ├── images/          # Изображения и диаграммы
│       └── examples/        # Исходные файлы для генерации
----

=== Шаг 3: Настройка конфигурации

==== Добавление компонента в config.yml

Добавьте новый компонент в файл tools/config.yml:

[source,yaml]
----
components:
  first-project:
    enabled: true
    title: "Мой первый проект"
    description: "Пример создания первого проекта в ODS"
    
    # Настройки генерации
    pdf:
      enabled: true
      theme: "report"
      
    # Настройки диаграмм
    drawio:
      enabled: true
      
    # Настройки списков
    list:
      pdf_lists: true
----

==== Добавление в antora-playbook.yml

Добавьте источник контента в файл antora-playbook.yml:

[source,yaml]
----
content:
  sources:
    - url: .
      branches: HEAD
      worktrees: true
      start_path: components/first-project
----

=== Шаг 4: Создание дополнительных страниц

После создания основных файлов можно добавить дополнительные страницы:

* about.adoc - описание проекта;
* features.adoc - основные функции;
* installation.adoc - инструкции по установке.

Каждая страница должна иметь правильную структуру заголовков и атрибуты AsciiDoc.

=== Шаг 5: Работа с шаблонами

==== Использование папки templates

Папка templates/ содержит примеры файлов, которые можно использовать как основу для создания новых документов.

Примеры файлов в templates:

[source,text]
----
templates/
├── diagrams/                 # Примеры диаграмм
│   └── puml/                # PlantUML диаграммы
│       ├── kts.puml         # Диаграмма классов
│       └── net.puml         # Сетевая диаграмма
├── glossary/                # Словари и термины
│   └── glossary.adoc        # Глоссарий
├── snippets/                # Фрагменты кода
│   ├── asciidoc-table.code-snippets
│   └── asciidoc.code-snippets
└── templates_doc/           # Шаблоны документов
    └── modules/
        ├── approval-page/   # Листы утверждения
        ├── oed/             # Опытно-эксплуатационная документация
        ├── ROOT/            # Основные шаблоны
        └── trd/             # Техническая документация
----

==== Копирование и адаптация шаблонов

Скопируйте нужный шаблон и адаптируйте под ваш проект:

[source,bash]
----
# Копирование шаблона технического задания
cp templates/templates_doc/modules/trd/pages/Частное_техническое_задание.adoc \
   components/first-project/modules/ROOT/pages/technical-spec.adoc

# Копирование шаблона листа утверждения
cp templates/templates_doc/modules/oed/pages/Акт_приемки_в_опытную_эксплуатацию.adoc \
   components/first-project/modules/ROOT/pages/acceptance-act.adoc

# Копирование PlantUML диаграммы
cp templates/diagrams/puml/kts.puml \
   components/first-project/modules/ROOT/examples/class-diagram.puml

# Редактирование файла
# Замените заголовки, описания и содержимое под ваш проект
----

=== Шаг 5: Настройка генерации

==== Настройка PDF генерации

Для настройки генерации PDF добавьте атрибуты в начало AsciiDoc файлов:

[source,adoc]
----
:doctype: book
:custom_title_page: original      # Тип титульной страницы
:custom_other_page: none         # Тип обычных страниц
:custom_list_type: alphabetic    # Тип нумерации списков
----

Доступные типы титульных страниц:

* original - стандартная титульная страница;
* contract - титульная страница для контрактов;
* original_frame - титульная страница с рамками;
* approval_page_gost - лист утверждения ГОСТ;
* none - без титульной страницы.

Доступные типы обычных страниц:

* original - с полными рамками и колонтитулами;
* original_frame - с рамками и приставкой;
* none - стандартное AsciiDoc оформление.

Доступные типы списков:

* alphabetic - уровень 2 тире (–);
* dash - уровень 2 буквы (а б в).

==== Настройка тем PDF

Система поддерживает автоматический выбор тем PDF:

* :pdf-theme: act - для актов с нумерацией с первой страницы;
* Автоматический выбор frame - для документов с рамками (_frame);
* Автоматический выбор report - для обычных документов.

Важно: атрибуты для конвертеров (например, :pdf-theme:, :custom_other_page:) должны быть определены непосредственно в основном файле документа. Атрибуты из файлов, подключенных через include::, недоступны для конвертеров Ruby.

Подробнее см. xref:Настроика_конвертеров_списков.adoc#работа-с-атрибутами-в-конвертерах[Работа с атрибутами в конвертерах].

==== Настройка диаграмм

Для включения диаграмм создайте файлы в папке examples/:

[source,text]
----
components/first-project/modules/ROOT/examples/
├── drawio/                   # Draw.io диаграммы
│   └── system-architecture.drawio
├── bpmn/                     # BPMN диаграммы
│   └── business-process.bpmn
└── plantuml/                 # PlantUML диаграммы
    └── class-diagram.puml
----

=== Шаг 6: Запуск генерации

==== Локальная генерация

Запустите генерацию документации:

[source,bash]
----
# Генерация всех компонентов
ruby tools/start.rb
----

Примечание: Скрипт start.rb обрабатывает все компоненты, указанные в config.yml. Для генерации только одного компонента создайте отдельный файл конфигурации с нужным компонентом.

==== Проверка результатов

После генерации проверьте созданные файлы:

[source,text]
----
components/first-project/modules/ROOT/attachments/
├── index.pdf                 # Главная страница
└── nav.pdf                  # Навигация (если создан)
----

=== Шаг 8: Тестирование и отладка

==== Проверка PDF генерации

Убедитесь, что PDF файлы генерируются корректно:

[source,bash]
----
# Проверка наличия PDF файлов
ls -la components/first-project/modules/ROOT/attachments/

# Проверка содержимого PDF
file components/first-project/modules/ROOT/attachments/index.pdf
----

==== Проверка Antora сборки

Запустите сборку Antora для проверки веб-версии:

[source,bash]
----
antora antora-playbook.yml
----

Проверьте результат в папке public/first-project/1/.

=== Шаг 9: Документирование и поддержка

==== Создание README

Создайте файл components/first-project/README.md с описанием компонента:

[source,markdown]
----
# Мой первый проект

Описание проекта и инструкции по использованию.

## Структура

- pages/ - основные страницы документации
- partials/ - части документов
- examples/ - примеры и шаблоны

## Генерация

Для генерации документации используйте:

[source,bash]
----
ruby tools/start.rb
----
----

==== Обновление документации

Регулярно обновляйте документацию при изменении проекта:

* Обновляйте описания функций;
* Добавляйте новые разделы;
* Исправляйте ошибки;
* Улучшайте структуру документов.

=== Заключение

Создание нового компонента в системе ODS включает в себя:

* Создание структуры папок;
* Настройку конфигурации;
* Создание основных документов;
* Настройку генерации PDF и веб-версии;
* Тестирование и отладку.

Следуя данному руководству, вы сможете создать полноценный компонент документации, который будет интегрирован в общую систему ODS.
