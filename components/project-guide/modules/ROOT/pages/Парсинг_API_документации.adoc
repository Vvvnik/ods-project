= Парсинг API документации
:sectnums:

== Назначение

Конвертер API документации предназначен для автоматической генерации AsciiDoc документации из OpenAPI/Swagger спецификаций.

== Принцип работы

Конвертер читает конфигурацию источников API из файла sources.yml и генерирует документацию в формате AsciiDoc:

. Загружает конфигурацию источников из файла sources.yml;
. Подключается к каждому указанному API endpoint;
. Парсит OpenAPI/Swagger спецификацию;
. Генерирует AsciiDoc файлы с описанием API;
. Сохраняет результат в папку partials/docs-api.

== Конфигурация

=== Секция api в config.yml

[source,yaml]
----
api:
  enabled: true # Включить/отключить генерацию API документации
  dst: "components/{name}/modules/ROOT/partials/docs-api" # Куда сохранять API документацию
  api_sources_file: "components/{name}/modules/ROOT/examples/sources.yml"  # Файл источников API
  erase_destination_folder: true # Очищать папку назначения перед генерацией
----

В файле sources.yml установите параметры для подключения к своим API. Файл sources.yml должен находиться в папке компонента в папке examples.

=== Структура файла sources.yml

Файл sources.yml содержит список API endpoints для парсинга:

[source,yaml]
----
sources:
  - name: "API Service 1"
    url: "https://api.example.com/swagger.json"
    description: "Описание первого API"
  - name: "API Service 2" 
    url: "https://api2.example.com/openapi.yaml"
    description: "Описание второго API"
----

=== Атрибуты источников

Каждый источник API может содержать следующие атрибуты:

==== Атрибут `description`
**Назначение:** Описание источника для логирования и отображения в консоли

**Использование:**
* Отображается в логах при обработке: `📝 Обрабатываем: {description}`
* Показывается в списке найденных источников
* Если не указан, используется путь к источнику

**Пример:**
[source,yaml]
----
- type: directory
  path: "components/toys-service/modules/ROOT/examples/api/"
  description: "Все файлы из папки api"
----

==== Атрибут `patterns`
**Назначение:** Маски файлов для поиска в папках (только для `type: directory`)

**Использование:**
* Фильтрует файлы по расширениям в указанной папке
* По умолчанию: `["*.json", "*.yaml", "*.yml"]`
* Используется в `Dir.glob()` для поиска файлов

**Пример:**
[source,yaml]
----
- type: directory
  path: "components/toys-service/modules/ROOT/examples/api/"
  description: "Все файлы из папки api"
  patterns: ["*.json", "*.yaml", "*.yml"]
----

:warning-caption: Внимание!
[WARNING]
====
Атрибуты `patterns` и `description` активно используются скриптом `openapi-swagger-adoc.rb` для фильтрации файлов и отображения информации в логах:

* `patterns` - **критически важен** для фильтрации файлов в папках. Если не задан, используется по умолчанию: `["*.json", "*.yaml", "*.yml"]`;
* `description` - **полезен** для информативности логов и отладки.

Без `patterns` скрипт не сможет найти нужные файлы в папках, а без `description` будет сложнее понять, какой именно источник обрабатывается в логах.
====

== Используемые технологии

* Ruby – основной язык скрипта;
* JSON/YAML – парсинг конфигурации;
* OpenAPI/Swagger – стандарты API документации;
* AsciiDoc – формат выходной документации.

== Результат работы

Конвертер создает следующие файлы:

. test-api-yml.adoc – главная страница API документации;
. test-api.adoc – альтернативная версия документации;
. swagger.adoc – документация в формате Swagger.

== Примеры использования

=== Запуск конвертера

В проекте скрипт запускается автоматически через главный скрипт `tools/start.rb`, который использует конфигурацию из `tools/config.yml` и файл источников API компонента.

[source,bash]
----
# Автоматический запуск через главный скрипт
ruby tools/start.rb

# Ручной запуск с указанием файла источников и выходной директории
ruby tools/scripts/openapi-swagger-adoc.rb --sources sources.yml --out output

# Ручной запуск с дополнительными параметрами
ruby tools/scripts/openapi-swagger-adoc.rb --sources sources.yml --in input_dir --out output
----

Параметры:

* `--sources` - путь к файлу sources.yml с конфигурацией API (обязательный)
* `--in` - входная директория (опционально)
* `--out` - выходная директория (обязательный)

При запуске через `tools/start.rb` параметры `--sources` и `--out` берутся из конфигурации `tools/config.yml` (секция `api`, поля `api_sources_file` и `dst`).

== Ограничения

* Поддерживаются только OpenAPI 3.0 и Swagger 2.0;
* Требуется доступ к API endpoint для получения спецификации;
* Генерируется только базовая документация без кастомизации.
