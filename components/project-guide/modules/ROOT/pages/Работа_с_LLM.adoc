== Обзор

Система использует LLM (Large Language Model) для автоматического перевода атрибутов базы данных. Поддерживается перевод на русский и английский языки с использованием локальной модели Ollama.

== Архитектура системы

=== Компоненты

* **LLMClient** - клиент для работы с Ollama;
* **TranslationUtils** - утилиты для работы со словарем и логом;
* **PromptLoader** - загрузчик промптов;
* **ConfigLoader** - загрузчик конфигурации;

=== Структура файлов

[source,text]
----
tools/
├── log/
│   └── database_translations_log.txt    # Лог переводов LLM
├── dictionary/
│   └── database_translations.yml       # Словарь переводов
├── prompts/
│   └── database_translations.prompt    # Универсальный промпт
└── lib/
    ├── llm_client.rb                   # Клиент LLM
    ├── translation_utils.rb            # Утилиты переводов
    └── prompt_loader.rb                # Загрузчик промптов
----

== Конфигурация

=== Настройки в config.yml

[source,yaml]
----
db:
  translate: "ru"                        # Язык перевода: "ru", "en", false
  dictionary: "tools/dictionary/database_translations.yml"
  prompt: "database_translations"
----

=== Поддерживаемые языки

* `"ru"` или `true` - перевод на русский;
* `"en"` - перевод на английский  ;
* `false` - отключить переводы;

== Логика работы

=== Алгоритм перевода

1. **Предварительный сбор**: Собираем все поля из БД для перевода (без генерации документации)
2. **Пакетный перевод**: Переводим все собранные поля через LLM одним запросом
3. **Генерация документации**: Создаем документацию с уже переведенными названиями
4. **Проверка комментария**: Если поле имеет комментарий в БД - используем его как есть
5. **Проверка словаря**: Ищем перевод в словаре (приоритет над LLM)
6. **Проверка языка**: Если перевод на другом языке - игнорируем и переводим заново
7. **Сохранение**: Результаты сохраняются в словарь и лог

=== Пакетная обработка

Система использует "супер ускорение" - вместо индивидуальных запросов к LLM собирает поля в пакеты по 50 штук:

**Новая последовательность работы:**
1. **Сбор полей**: Проходим по всем таблицам БД и собираем поля для перевода
2. **Пакетный перевод**: Переводим все поля одним запросом к LLM
3. **Генерация документации**: Создаем документацию с уже переведенными названиями

[source,ruby]
----
# Сбор полей для перевода
MISSING_FIELDS = []

# Обработка пакета
def process_batch_translation(llm_client, translation_utils, translate_comments)
  batches = MISSING_FIELDS.each_slice(50).to_a
  batches.each do |batch|
    translations = llm_client.translate_batch(batch, translate_comments)
    # Сохранение результатов
  end
end
----

== Словарь переводов

=== Формат файла

[source,yaml]
----
# Словарь переводов атрибутов базы данных
# Формат: оригинальное_имя: "перевод"

---
translations:
  user_id: Идентификатор пользователя
  created_at: Дата создания
  updated_at: Дата обновления
----

=== Автоматическое пополнение

Словарь автоматически пополняется новыми переводами при каждом запуске. Повторные переводы не выполняются.

== Лог переводов

=== Формат лога

[source,text]
----
# Лог переводов LLM
# Обновляется при каждом запуске

2025-10-21 00:50:08 | aircrafts_data → Данные о самолетах
2025-10-21 00:50:08 | airports_data → Данные о аэропортах
----

=== Очистка лога

Лог очищается при каждом запуске скрипта с флагом `--use-llm`.

== Промпт

=== Универсальный промпт

Используется единый промпт `database_translations.prompt` для всех случаев перевода:

[source,text]
----
Переведи следующие поля базы данных на <%= target_language %> язык:

<% fields.each_with_index do |field, index| %>
<%= index + 1 %>. <%= field %>
<% end %>

Требования:
<% if target_language == "русский" %>
- Переведи каждое слово точно на русский
- Замени подчеркивания на пробелы
- Начинай с заглавной буквы
- Отвечай ТОЛЬКО переводом, без объяснений
- Не добавляй слова "поле", "атрибут", "данные" если их нет в оригинале

Примеры:
user_id → Идентификатор пользователя
created_at → Дата создания
<% else %>
- Преврати snake_case в читаемые слова
- Замени подчеркивания на пробелы
- Начинай с заглавной буквы
- Отвечай ТОЛЬКО переводом, без объяснений
- Не добавляй слова "field", "attribute", "data" если их нет в оригинале

Примеры:
user_id → User ID
created_at → Created at
<% end %>
----

== Производительность

=== Сравнение скорости

* **Индивидуальный перевод**: 50 полей = 50 запросов к LLM (~50-100 секунд);
* **Пакетный перевод**: 50 полей = 1 запрос к LLM (~2-5 секунд);
* **Экономия времени**: 45-95 секунд;

=== Кэширование

Система использует кэш переводов для избежания повторных запросов:

[source,ruby]
----
TRANSLATION_CACHE = {}

def translate_field(name, comment, translate_comments, llm_client, translation_utils)
  cache_key = "#{name}_#{translate_comments}"
  return TRANSLATION_CACHE[cache_key] if TRANSLATION_CACHE.key?(cache_key)
  # ... логика перевода
end
----

== Ограничения

=== Требования к LLM

* Локальная установка Ollama;
* Модель `gemma:latest` или совместимая;
* Доступность сервера на `http://localhost:11434`;

=== Fallback механизм

При недоступности LLM система использует простую конвертацию:

[source,ruby]
----
def create_fallback_translation(text)
  text.gsub(/([a-z])([A-Z])/, '\1 \2')
      .tr('_', ' ')
end
----

== Локальное использование

Система LLM предназначена для **локального использования** на машине разработчика. Это обеспечивает:

* **Быстрый доступ** к Ollama без сетевых задержек;
* **Полный контроль** над моделями и настройками;
* **Безопасность** - данные не передаются во внешние сервисы;
* **Стабильность** - не зависит от доступности внешних API;

=== Требования к локальной среде

1. **Установленный Ollama**: Локальный сервер Ollama
2. **Загруженная модель**: `gemma:latest` или аналогичная
3. **Запущенный сервер**: `ollama serve` должен работать
4. **Ruby окружение**: Все необходимые гемы установлены

==== Создание нового скрипта

Создайте скрипт для обработки API документации:

[source,ruby]
----
# tools/scripts/api_to_adoc.rb

require_relative '../lib/config_loader'
require_relative '../lib/llm_client'
require_relative '../lib/translation_utils'

# Загрузка конфигурации
config = ConfigLoader.load_config

# Инициализация LLM клиента
llm_client = LLMClient.new(
  config.dig('ollama', 'host'),
  config.dig('ollama', 'model'),
  config.dig('api', 'prompts'),
  config.dig('api', 'prompt')
)

# Инициализация утилит переводов
translation_utils = TranslationUtils.new(
  config.dig('api', 'dictionary'),
  config.dig('api', 'log')
)

# Основная логика обработки
def translate_api_doc(api_doc, translate_comments, llm_client, translation_utils)
  # Проверяем словарь
  if translation_utils.has_translation?(api_doc)
    return translation_utils.get_translation(api_doc)
  end
  
  # Переводим через LLM
  translation = llm_client.translate_batch([api_doc], translate_comments)
  
  # Сохраняем в словарь
  translation_utils.add_translation(api_doc, translation[api_doc])
  
  translation[api_doc]
end

# Использование
api_doc = "Get user information"
translated = translate_api_doc(api_doc, "ru", llm_client, translation_utils)
puts translated  # "Получить информацию о пользователе"
----
