== Этапы генерации документации

Все этапы генерации документации выполняются автоматически через скрипт start.rb.

Однако, в случае необходимости, можно выполнить генерацию документации вручную.

:num_t: {counter:table-number}

== Работа с диаграммами

=== Генерация через start.rb

Для генерации BPMN и Draw.io диаграмм через основной скрипт:

. Включите генерацию в tools/config.yml:
.. Запустите генерацию:

Результат:

* BPMN: исходники в modules/ROOT/examples/bpmn/ → modules/ROOT/images/bpmn/*.svg;
* Draw.io: исходники в modules/ROOT/examples/drawio/ → modules/ROOT/images/drawio/*.svg;

=== Ручная генерация диаграмм

Для ручной генерации BPMN и Draw.io диаграмм используйте скрипты:

[source,bash]
----
# Генерация BPMN диаграмм
node tools/scripts/bpmn_to_img.js --in components/component-name/modules/ROOT/examples/bpmn --out components/component-name/modules/ROOT/images/bpmn --format svg

# Генерация Draw.io диаграмм  
node tools/scripts/drawio_to_img.js --in components/component-name/modules/ROOT/examples/drawio --out components/component-name/modules/ROOT/images/drawio --format svg
----

=== Kroki диаграммы

Для PlantUML диаграмм используйте Kroki (работает автоматически):


[kroki-plantuml, format=svg]
----
@startuml
A --> B
@enduml
----


=== Зависимости для рендеринга
Необходимые зависимости для рендеринга диаграмм:

* BPMN: Puppeteer + Chrome/Chromium (только локально);
* Draw.io: Draw.io Desktop приложение (только локально);
* PlantUML: Kroki сервер (автоматически в CI и локально);

:tip-caption: Примечание

[TIP]
В CI/CD генерация BPMN и Draw.io диаграмм отключена автоматически.

См. подробности в разделе <<Установка, Установка>>.

== Генерация PDF с титульными страницами

Для генерации PDF документов с кастомными титульными страницами используйте команду:

[source,bash]
----
asciidoctor-pdf \
  -r asciidoctor-kroki \
  -r ./tools/scripts/convert_ascii_to_pdf.rb \
  -a kroki-default-format=png \
  -a kroki-server-url=http://localhost:8000 \
  -a pdf-theme=report \
  -a pdf-themesdir=resources/themes \
  -a pdf-fontsdir=resources/fonts \
  -a allow-uri-read \
  components/information-system/modules/trd/pages/Описание_постановки_задачи.adoc
----

=== Параметры команды

* -r asciidoctor-kroki - подключение Kroki для диаграмм;
* -r ./tools/scripts/convert_ascii_to_pdf.rb - унифицированный конвертер с автоматическим выбором тем и типов списков;
* -a kroki-server-url=http://localhost:8000 - URL локального сервера Kroki;
* -a pdf-theme=report - тема для PDF (автоматически выбирается: frame для _frame типов, report для остальных);
* -a pdf-themesdir=resources/themes - директория с темами;
* -a pdf-fontsdir=resources/fonts - директория со шрифтами;
* -a allow-uri-read - разрешение чтения внешних ресурсов;

=== Типы титульных страниц

* :custom_title_page: *original* - для обычных документов;
* :custom_title_page: *contract* - для контрактных документов;
* :custom_title_page: *original_frame* - с рамками и приставкой;
* :custom_title_page: *approval_page_gost* - лист утверждения в стиле ГОСТ;
* :custom_title_page: *none* - без титульной страницы;

=== Отключение титульной страницы

Для полного отключения титульной страницы используйте:

[source,asciidoc]
----
:doctype: book
:custom_title_page: none
:custom_other_page: none
:notitle:

== Название документа
----

:warning-caption: Внимание  

[WARNING]
Используйте заголовок уровня 2 (==) вместо уровня 1 (=), чтобы избежать создания титульной страницы.

=== Правильное использование заголовков

Если НЕ задан тип титульной страницы (:custom_title_page: не указан или пустой):

[source,asciidoc]
----
:doctype: book
:custom_other_page: none

== Название документа

Содержание документа начинается сразу после заголовка...
----

Если задан тип титульной страницы (:custom_title_page: contract, :custom_title_page: original, :custom_title_page: original_frame или :custom_title_page: approval_page_gost):

[source,asciidoc]
----
:doctype: book
:custom_title_page: original
:custom_other_page: none

== Название документа

Содержание документа начинается после титульной страницы...
----

Ключевое правило:

* = (уровень 1) + :custom_title_page: = титульная страница + содержание;
* == (уровень 2) + отсутствие :custom_title_page: = только содержание без титульной страницы;

:warning-caption: Внимание  

[WARNING]
Если :custom_title_page: не задан или пустой, система автоматически использует тип none и не создает титульную страницу. Это поведение по умолчанию безопасно для большинства документов.

=== Логика работы системы титульных страниц

Что происходит при разных значениях :custom_title_page:

. :custom_title_page: contract → загружается модуль ConvertTitlePageContract;
. :custom_title_page: original → загружается модуль ConvertTitlePageOriginal;
. :custom_title_page: original_frame → загружается модуль ConvertTitlePageOriginalFrame;
. :custom_title_page: approval_page_gost → загружается модуль ConvertApprovalPageGost;
. :custom_title_page: none → модуль не загружается, титульная страница отключена;
. :custom_title_page: (пустой) → система использует значение по умолчанию 'none' → модуль не загружается, титульная страница отключена;
. Атрибут не задан → система использует значение по умолчанию 'none' → модуль не загружается, титульная страница отключена.

Конфигурация типов страниц находится в файле tools/config_type_page.yml:

[source,yaml]
----
title_pages:
  original: "convert_title_page_original"
  contract: "convert_title_page_contract"
  original_frame: "convert_title_page_original_frame"
  approval_page_gost: "convert_approval_page_gost"
  none: null
----

=== Поведение при отключенных титульных страницах

Когда :custom_title_page: none или атрибут не задан:

. Кастомные конвертеры не загружаются - модули ConvertTitlePageContract, ConvertTitlePageOriginal, ConvertTitlePageOriginalFrame и ConvertApprovalPageGost не включаются;
. Используется стандартный Asciidoctor PDF - вызывается super(doc) вместо кастомной обработки;
. Стандартная титульная страница Asciidoctor - если есть заголовок уровня 1 (=), создается стандартная титульная страница;
. Настройки из темы - все стили, шрифты, цвета, отступы берутся из report-theme.yml или другой темы.

:warning-caption: Внимание  

[WARNING]
При использовании атрибута custom_title_page: none заголовок уровня 1 (=) все равно создает стандартную титульную страницу Asciidoctor. Чтобы избежать этого, используйте заголовок уровня 2 (==) или добавьте атрибут :notitle.

Пример конфигурации темы:

[source,yaml]
----
# resources/themes/report-theme.yml
extends: default

font:
  catalog:
    Times:
      normal: times-new-roman-normal.ttf
      bold: times-new-roman-bold.ttf
      italic: times-new-roman-italic.ttf
      bold_italic: times-new-roman-bold-italic.ttf

page:
  margin: [15mm, 7mm, 25mm, 20mm]
  size: A4

footer:
  recto:
    right: '{page-number}'
  verso:
    left: '{page-number}'
----

Примеры правильного использования:

Неправильно (создаст стандартную титульную страницу Asciidoctor):

[source,asciidoc]
----
= Название документа
:custom_title_page: none

== Документ
----

Правильно (без титульной страницы):

[source,asciidoc]
----
:custom_title_page: none
:notitle:

== Документ
----


Или используйте заголовок уровня 2:

[source,asciidoc]
----
:custom_title_page: none

== Документ
----

:warning-caption: Внимание  

[WARNING]
При использовании атрибута custom_title_page: none система полностью полагается на настройки темы. 

Убедитесь, что в config.yml правильно указана тема:

[source,yaml]
----
pdf:
  theme: "report"  # или ваша пользовательская тема
  themes_dir: "resources/themes"
----

== Полная проверка

=== Запуск команд

[source,bash]
----
# Генерация всей документации
ruby ./tools/start.rb

# Запуск локального сайта
npx antora --attribute kroki-server-url=http://localhost:8000 antora-playbook.yml
----

=== Варианты запуска Antora

Существует два способа запуска Antora:

=== Использование NPX (рекомендуется)

[source,bash]
----
npx antora --attribute kroki-server-url=http://localhost:8000 antora-playbook.yml
----

Преимущества NPX:

* Работает даже если Antora не установлена глобально;
* Использует локальную версию из node_modules;
* Больше совместимости между разными средами;
* Стандартный подход в Node.js экосистеме;

:warning-caption: Важно

[NOTE]
CLI параметр `--attribute kroki-server-url=http://localhost:8000` переопределяет значение из `antora-playbook.yml`. 
Это позволяет оставить в конфигурации URL для CI (`http://kroki:8000`) и не менять файл вручную при локальной разработке.


=== Использование глобальной установки Antora

[source,bash]
----
antora antora-playbook.yml
----

Минусы прямой команды:

* Требует глобальной установки Antora (npm install -g @antora/cli);
* Пользователь должен иметь права для глобальной установки пакетов;
* Возможны конфликты версий между проектами;

Рекомендация: Используйте npx antora antora-playbook.yml – он более надежен и будет работать у большего количества пользователей.
