= Настройка config.yml
:sectnums:
Проект настраивается через центральный файл tools/config.yml.

== Секции конфигурации

[cols="1,2,3", options="header, breakable"]
|===
^|Секция ^|Параметр ^|Описание

|themes_dir
|Путь к темам PDF
|Директория с файлами тем для PDF генерации

|defaults
|Настройки по умолчанию
|Общие параметры для всех компонентов (bpmn, drawio, api, db, pdf, list)

|components
|Список компонентов
|Конфигурация каждого компонента с переопределением defaults
|===

=== Настройки БД и API

Настройки БД и API источников находятся в компонентах:

* components/{name}/modules/ROOT/examples/database.yml – профили БД;
* components/{name}/modules/ROOT/examples/sources.yml – источники API;

Путь к настройкам БД и API источников задается в файле tools/config.yml в секции defaults через параметры:

* `database_connect_file` – путь к файлу подключения к БД;
* `api_sources_file` – путь к файлу источников API;

== Пример конфигурации компонента

[source,yaml]
----
- name: airport-service
  <<: *defaults
  db:
    enabled: true
    profile: "pg_demo"
  pdf:
    enabled: true

- name: toys-service
  <<: *defaults
  api:
    enabled: true
    api_sources_file: "components/{name}/modules/ROOT/examples/sources.yml"
----

:tip-caption: Примечание

[TIP]
В реальной конфигурации большинство компонентов закомментированы для ускорения сборки. Для включения компонента раскомментируйте соответствующие секции.

== Управление компонентами в config.yml

Файл `tools/config.yml` управляет генерацией документации для всех компонентов. Компоненты настраиваются в секции `components`.

=== Добавление нового компонента

Добавьте новую запись в секцию `components`:

[source,yaml]
----
components:
  - name: my-new-project
    <<: *defaults
    pdf:
      enabled: true
    drawio:
      enabled: true
----

Где:

* `name` – имя компонента (должно соответствовать папке в `components/`);
* `<<: *defaults` – наследование настроек по умолчанию;
* Далее переопределяются нужные секции (pdf, drawio, api, db, bpmn, list).

=== Включение компонента

Чтобы включить генерацию для компонента, раскомментируйте нужные секции:

[source,yaml]
----
components:
  - name: airport-service
    <<: *defaults
    # Раскомментировать для включения:
    db:
      enabled: true
      profile: "pg_demo"
    pdf:
      enabled: true
----

=== Отключение компонента

Чтобы временно отключить компонент, закомментируйте всю запись или отдельные секции:

[source,yaml]
----
components:
  # Временно отключенный компонент:
  # - name: old-component
  #   <<: *defaults
  #   pdf:
  #     enabled: true
  
  - name: active-component
    <<: *defaults
    # Отключена только PDF генерация:
    # pdf:
    #   enabled: true
    drawio:
      enabled: true
----

Отключенный компонент не будет обрабатываться скриптом `tools/start.rb`.

=== Удаление компонента

Чтобы полностью удалить компонент из сборки:

. Удалите запись из секции `components` в `tools/config.yml` (или закомментируйте);
. При необходимости удалите компонент из `antora-playbook.yml` (если он там указан);
. При необходимости удалите папку компонента из `components/`.

[source,yaml]
----
components:
  # Удаленная запись для old-component
  - name: active-component
    <<: *defaults
    pdf:
      enabled: true
----

:warning-caption: Внимание

[WARNING]
Удаление компонента из `config.yml` не удаляет его файлы из папки `components/`. Для полного удаления нужно вручную удалить папку компонента.

=== Отключение отдельных функций компонента

Можно отключить отдельные функции генерации для компонента, оставив его в списке:

[source,yaml]
----
components:
  - name: my-component
    <<: *defaults
    # Все функции отключены, но компонент остается в списке:
    # bpmn:
    #   enabled: true
    # drawio:
    #   enabled: true
    # api:
    #   enabled: true
    # db:
    #   enabled: true
    # pdf:
    #   enabled: true
    # list остается включенным по умолчанию
----

== Основные параметры конфигурации

=== Глобальные параметры

* `themes_dir` – путь к директории с темами PDF (по умолчанию: "resources/themes");

=== Параметры секции defaults

==== BPMN диаграммы (bpmn:)

* `enabled` – включить/отключить генерацию BPMN;
* `src` – исходная директория с .bpmn файлами;
* `dst` – целевая директория для изображений;
* `erase_destination_folder` – очищать папку назначения;

==== Draw.io диаграммы (drawio:)

* `enabled` – включить/отключить генерацию Draw.io;
* `src` – исходная директория с .drawio файлами;
* `dst` – целевая директория для изображений;
* `erase_destination_folder` – очищать папку назначения;

==== API документация (api:)

* `enabled` – включить/отключить генерацию API документации;
* `dst` – целевая директория для API документации;
* `api_sources_file` – путь к файлу источников API;
* `erase_destination_folder` – очищать папку назначения;

==== База данных (db:)

* `enabled` – включить/отключить генерацию DB документации;
* `images_dir` – папка для изображений схем БД;
* `dst` – целевая директория для DB документации;
* `database_connect_file` – путь к файлу подключения к БД;
* `profile` – профиль БД для подключения;
* `erase_destination_folder` – очищать папку назначения;

==== PDF генерация (pdf:)

* `enabled` – включить/отключить генерацию PDF;
* `src` – исходная директория с .adoc файлами;
* `dst` – целевая директория для PDF файлов;
* `converter` – путь к конвертеру PDF;
* `theme` – тема оформления PDF;
* `themes_dir` – папка с темами;
* `fonts_dir` – папка со шрифтами;
* `exclude_files` – файлы исключаемые из генерации;
* `use_title_pages` – использовать титульные страницы;

==== Списки файлов (list:)

* `enabled` – включить/отключить генерацию списков;
* `adoc_lists` – списки .adoc файлов;
* `pdf_lists` – PDF списки (только при включенной PDF генерации);
* `adoc_src` – исходная директория с .adoc файлами;
* `pdf_src` – исходная директория с PDF файлами;
* `dst` – целевая директория для списков;

== Рекомендации

* Не включайте парсинг БД и API по умолчанию;
* Используйте вложенные секции (bpmn:, drawio:, api:, db:, pdf:, list:) для управления генерацией;
* Настройте kroki_url для обработки PlantUML диаграмм;

== Конфигурирование сборки диаграмм

=== Проблема с путями к изображениям

При использовании диаграмм в разных модулях компонента возникает проблема с путями к изображениям:

* ROOT модуль подходит для изображений, которые нужны и в PDF и в Antora, НО ТОЛЬКО если AsciiDoc файл, ссылающийся на них, находится в модуле ROOT;
* Проблема возникает когда AsciiDoc файл находится в модуле ed, а изображения в модуле ROOT;
* Путь image::drawio/diagrams_diagram-1.svg[] не работает и для PDF, и для Antora, потому что :imagesdir: ../images указывает на modules/ed/images/, а не на modules/ROOT/images/;

=== Решения

==== Решение 1: Размещение изображений в том же модуле

Размещать изображения в том же модуле, где находится AsciiDoc файл, и конфигурировать генерацию диаграмм для каждого модуля отдельно:

[source,yaml]
----
- name: information-system
  <<: *defaults
  drawio:
    enabled: true
    dst: "components/{name}/modules/ed/images/drawio"

- name: information-system
  <<: *defaults
  drawio:
    enabled: true
    dst: "components/{name}/modules/trd/images/drawio"

- name: information-system
  <<: *defaults
  drawio:
    enabled: true
    dst: "components/{name}/modules/ROOT/images/drawio"
----

Преимущества:

* Простые пути image::drawio/diagrams_diagram-1.svg[];
* Работает и в PDF, и в Antora;
* Не требует условной логики;

==== Решение 2: Условная логика с env-antora

Использовать условную логику в модуледля разных путей в PDF и Antora:

[source,adoc]
----
:imagesdir: ../images
\ifdef::env-antora[]
image::ROOT:drawio/diagrams_diagram-1.svg[] # ROOT или имя модуля
\endif::[]
\ifndef::env-antora[]
image::../../ROOT/images/drawio/diagrams_diagram-1.svg[] 
\endif::[]
----

Переменная env-antora:

* Определяется в antora-playbook.yml;
* Активна при сборке Antora;
* Позволяет использовать разные пути для PDF и Antora;

=== Глобальные настройки

PDF и списки работают для всех модулей компонента автоматически:

[source,yaml]
----
- name: information-system
  <<: *defaults
  pdf:
    enabled: true
    use_title_pages: true
  list:
    pdf_lists: true
----

Результат:

* PDF генерируется со всех модулей (ed, trd, oed) и сохраняется в ROOT/attachments/;
* Списки создают навигацию по всем модулям и сохраняют в ROOT/partials/;

=== Рекомендации по диаграммам

* Для диаграмм в разных модулях: используйте Решение 1 – отдельную конфигурацию для каждого модуля;
* Для общих диаграмм: используйте Решение 2 – условную логику с env-antora;
* PDF и списки: настраивайте один раз для всего компонента.
