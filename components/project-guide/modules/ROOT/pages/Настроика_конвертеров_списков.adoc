= Настройка конвертеров списков
:sectnums:
Документ описывает систему выборочных конвертеров для обработки списков в PDF генерации.

== Обзор системы

Система позволяет выбирать различные стили нумерации списков в PDF документах через атрибут :custom_list_type:.

Дополнительно система автоматически выбирает подходящую тему PDF:

* Тема frame – для документов с рамками (типы страниц с суффиксом _frame);
* Тема report – для обычных документов.

Это обеспечивает оптимальное оформление документов с учетом их типа.

Файлы тем frame-theme.yml и report-theme.yml находятся в директории resources/themes.

=== Связь с другими конвертерами

Система списков является частью общей модульной архитектуры PDF конвертеров. Подробнее об архитектуре системы см. xref:Настроика_тем_страниц.adoc#архитектура-системы-конвертеров[Архитектура системы конвертеров].

=== Поддерживаемые типы списков

Оба типа списков используют одинаковую логику нумерации:

dash::
Стиль с тире на втором уровне.

+

Логика нумерации:

. Уровень 1: 1) 2) 3).
. Уровень 2: тире –.
. Уровень 3+: тире –.

alphabetic::
Стиль с буквами на втором уровне.

+

Логика нумерации:

. Уровень 1: 1) 2) 3).
. Уровень 2: а) б) в).
. Уровень 3+: тире –.

Примечание: Типы `dash` и `alphabetic` различаются логикой нумерации на втором уровне: `dash` использует тире (–), а `alphabetic` использует буквы (а) б) в)).

== Настройка в документах

=== Настройка в отдельных документах

Для выбора типа списков добавьте в ваш документ:

[source]
----
:custom_list_type: dash
----

Или для альтернативного стиля:

[source]
----
:custom_list_type: alphabetic
----

=== Централизованная настройка для всего компонента

Для обеспечения единообразия документации рекомендуем устанавливать атрибут в файле attr_common.adoc компонента.

Файл modules/ROOT/partials/attr_common.adoc:

[source]
----
:custom_list_type: alphabetic
----

Это гарантирует, что все документы в компоненте будут использовать одинаковый стиль нумерации списков.

Переопределение настроек на уровне документа по-прежнему возможно.

=== Примеры списков

Так выглядит список со стилем dash:

[source]
----
. Первый пункт;
.. Подпункт;
.. Подпункт;
.. Подпункт;
... Дополнительный тире;
... Еще один тире;
. Второй пункт.
----

Результат:

[literal]
----

    а) Подпункт;
    б) Подпункт;
    в) Подпункт;
        – Дополнительный тире;
        – Еще один тире;
2) Второй пункт.
----

== Архитектура системы

=== Конфигурация

Настройка типов конвертеров в tools/config_type_page.yml:

[source,yaml]
----
list_types:
  alphabetic: "convert_list_alphabetic"
  dash: "convert_list_dash"
----

==== Альтернативная конфигурация

Для больших проектов с множеством конвертеров списков можно вынести конфигурацию в отдельный файл tools/config_type_list.yml:

[source,yaml]
----
# tools/config_type_list.yml
list_types:
  # Стандартные стили
  alphabetic: "convert_list_alphabetic"
  dash: "convert_list_dash"
  
  # Специализированные стили
  gost: "convert_list_gost"
  legal: "convert_list_legal"
  academic: "convert_list_academic"
  roman: "convert_list_roman"
----

Преимущества отдельного файла:

* Лучшая организация конфигурации;
* Упрощение основного файла config_type_page.yml;
* Возможность версионирования конвертеров списков отдельно;
* Удобство для командной работы.

Подключение в основном конвертере:
[source,ruby]
----
def load_config
  # Загружаем основную конфигурацию
  @config = YAML.load_file('tools/config_type_page.yml')
  
  # Загружаем конфигурацию списков, если файл существует
  list_config_path = 'tools/config_type_list.yml'
  if File.exist?(list_config_path)
    list_config = YAML.load_file(list_config_path)
    @config['list_types'] = list_config['list_types'] if list_config['list_types']
  end
end
----

=== Структура файлов

*kernel converter* convert_ascii_to_pdf.rb::
Основной конвертер с логикой выбора модулей.

*alphabetic module* convert_list_alphabetic.rb::
Модуль для alphabetic стиля списков.

*dash module* convert_list_dash.rb::
Модуль для dash стиля списков.

=== Алгоритм работы

. Документ загружается с атрибутом :custom_list_type:.
. CustomPDFConverter читает конфигурацию из config_type_page.yml.
. Соответствующий модуль динамически загружается и включается.
. Все методы обработки списков переопределяются модулем.
. PDF генерируется с выбранным стилем нумерации.

== Технические детали

=== Динамическая загрузка модулей

Система использует динамическую загрузку Ruby модулей:

[source,ruby]
----
def load_list_converter_module(doc)
  custom_list_type = doc.attr('custom_list_type')
  list_types = @config['list_types'] || {}
  module_name = list_types[custom_list_type]
  
  case module_name
  when "convert_list_alphabetic"
    require_relative 'convert_list_alphabetic'
    @list_converter_module = ConvertListAlphabetic
  when "convert_list_dash"
    require_relative 'convert_list_dash'  
    @list_converter_module = ConvertListDash
  end
  
  self.class.include(@list_converter_module)
end
----

=== Переопределяемые методы

Каждый модуль переопределяет следующие методы:

* convert_ulist(node)::

Обработка ненумерованных списков.

* convert_olist(node)::

Обработка нумерованных списков с выбором маркеров.

* convert_list(node)::

Общая логика обработки списков.

* convert_list_item(node, list, opts)::

Формирование маркеров для элементов списка.

=== Примеры специализированных конвертеров

==== Конвертер для ГОСТ документов

[source,ruby]
----
module ConvertListGost
  def convert_list_item(node, list, opts = {})
    case node.level
    when 1
      marker = "#{@list_numerals.size + 1})"
    when 2
      marker = "#{('а'.ord + (@list_numerals.size % 32)).chr})"
    else
      marker = "–"
    end
    
    "#{marker} #{node.text}"
  end
end
----

==== Конвертер для юридических документов

[source,ruby]
----
module ConvertListLegal
  def convert_list_item(node, list, opts = {})
    case node.level
    when 1
      marker = "#{@list_numerals.size + 1}."
    when 2
      marker = "#{('а'.ord + (@list_numerals.size % 32)).chr}."
    when 3
      marker = "#{@list_numerals.size + 1})"

      marker = "–"

  end
end

== Работа с атрибутами в конвертерах

=== Важное ограничение

Конвертеры Ruby имеют критическое ограничение при работе с атрибутами AsciiDoc:

Конвертеры могут читать только атрибуты, определенные непосредственно в обрабатываемом файле.

Атрибуты из файлов, подключенных через include::, недоступны для конвертеров Ruby.

=== Два способа чтения атрибутов

==== Чтение из файла напрямую

Используется в pdf_generator.rb для извлечения атрибутов :pdf-theme: и :custom_other_page::

[source,ruby]
----
def self.extract_pdf_theme_from_document(adoc_file)
  File.readlines(adoc_file, encoding: 'UTF-8').each do |line|
    line = line.strip
    if line.start_with?(':pdf-theme:')
      theme = line.sub(':pdf-theme:', '').strip
      return theme unless theme.empty?
    end
  end
  nil
end
----

Ограничение: читает только атрибуты, определенные в самом файле.

==== Чтение через объект документа

Используется в approval_page_generator.rb для извлечения атрибутов из обработанного документа:

[source,ruby]
----
def self.extract_attributes_from_doc(doc)
  attrs = {}
  attrs['name_dokument_master'] = doc.attr('name_dokument_master') || ''
  attrs['code'] = doc.attr('code') || ''
  # ... другие атрибуты
  attrs
end
----

Преимущество: читает атрибуты после обработки всех include:: файлов.

=== Практические примеры

==== Пример 1: Атрибуты в основном файле

[source,asciidoc]
----
:pdf-theme: act
:custom_other_page: original_frame
:name_dokument_master: Техническое задание

// include::../../ROOT/partials/contract.adoc[]
----

Результат: конвертеры могут прочитать :pdf-theme:, :custom_other_page:, :name_dokument_master:.

==== Пример 2: Атрибуты в include файле

[source,asciidoc]
----
// include::../../ROOT/partials/contract.adoc[]

= Документ
----

Где contract.adoc содержит:
[source,asciidoc]
----
:year: 2025
:signer_1_name: И.И. Иванов
----

Результат: конвертеры НЕ МОГУТ прочитать :year: и :signer_1_name: при использовании метода 1.

=== Рекомендации

* Для конвертеров: используйте только атрибуты, определенные в основном файле документа;
* Для include файлов: используйте атрибуты только для подстановки в текст документа;
* Для сложной логики: используйте метод 2 (через объект документа) в специальных генераторах.

=== Обходные решения

Если конвертеру нужны атрибуты из include файлов:

* Дублирование атрибутов в основном файле;
* Использование генераторов (как approval_page_generator.rb) вместо конвертеров;
* Предварительная обработка файлов для извлечения атрибутов.

== Поддержка

Система автоматически:

* Загружает нужные модули;
* Проверяет корректность конфигурации;
* Выводит отладочную информацию при загрузке;
* Обрабатывает ошибки при отсутствии модулей.
