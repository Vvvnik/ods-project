## ODS-6

### Разработать Сервис управления пользователями

<!-- //tag::ODS-6[] -->
Разработан Сервис управления пользователями – это готовое REST API для централизованного управления данными пользователей, реализованное с использованием технологического стека Spring Boot и PostgreSQL. Сервис обеспечивает полный цикл работы с пользователями, начиная от проектирования контрактов API и заканчивая внедрением комплексной бизнес-логики и механизмов аудита.

Ниже описан функционал сервиса:

**Управление ресурсами пользователей (User CRUD)**
Сервис предоставляет стандартизированный набор эндпоинтов для работы с основной сущностью "Пользователь", включая создание, получение, обновление и удаление данных.
- Эндпоинт `POST /api/v1/users` позволяет создать нового пользователя, используя заданные модели запросов и ответов.
- Методы доступа к существующему ресурсу реализованы для получения данных по уникальному ID (`GET /api/v1/users/{id}`), обновления (`PUT /api/v1/users/{id}`) или удаления (`DELETE /api/v1/users/{id}`).
- Для получения списка пользователей предусмотрена поддержка пагинации, что позволяет эффективно загружать большие объемы данных.

**Повышение надежности и бизнес-логика**
В сервис внедрены дополнительные проверки и правила для гарантии целостности и полноты данных.
- Проведена реализация строгой бизнес-валидации входных данных, которая включает проверку формата электронной почты и минимальной длины имени пользователя.
- Механизм обработки конфликтов данных гарантирует, что попытка создать пользователя с уже существующим адресом электронной почты вызовет ошибку `409 Conflict`.
- Внедрен модуль аудита действий, который автоматически фиксирует все значимые операции (создание, обновление, удаление) пользователей в отдельной таблице `user_audit`, включая исполнителя, тип и время действия.

**Расширенный функционал и обработка запросов**
Для удобства пользователя и повышения отказоустойчивости добавлены расширенные возможности запроса и обработки ошибок.
- Реализован расширенный поиск пользователей, позволяющий искать записи по частичному совпадению заданного email (`GET /api/v1/users?emailContains=...`).
- Поддерживается сортировка списка пользователей по параметрам запроса, например, по имени (`name`) или времени создания (`createdAt`).
- В архитектуру добавлены глобальные обработчики исключений, что обеспечивает возвращение структурированных JSON-объектов с кодом и сообщением об ошибке при срабатывании валидации, ошибках БД или других исключениях.

## ODS-10

### Исправить ошибку обработки пагинации в эндпоинте GET /api/v1/users сервиса управления пользователями

<!-- //tag::ODS-10[] -->
В рамках задачи ODS-10 была реализована критическая доработка механизма пагинации в эндпоинте `GET /api/v1/users` сервиса управления пользователями. Основная цель – устранение некорректной обработки параметров постраничного получения списка пользователей, чтобы исключить возврат полного набора данных, что снижало нагрузку на сеть и клиентское приложение.

Основные изменения включают:

*   Изменена реализация метода контроллера `UserController.getUsers`, которая теперь обеспечивает корректную передачу параметров пагинации (`page`, `size`) в слой доступа к данным с использованием стандартных механизмов Spring Data JPA.
*   Обновлена структура JSON-ответа для соответствия стандартам пагинации API. Ответ включает обязательные поля: `content` (массив пользователей текущей страницы), а также служебные поля: `totalPages`, `totalElements`, `size`, `number`, `first` и `last`.
*   Добавлена обязательная валидация входных параметров запроса, что повышает стабильность работы API:
    1.  Если предоставлен параметр `page`, он должен быть неотрицательным числом (`page >= 0`), в противном случае возвращается статус 400 Bad Request.
    2.  Параметр `size` должен находиться в диапазоне от 1 до 100 (`1 <= size <= 100`), иначе возвращается статус 400 Bad Request.
*   Установлены параметры по умолчанию для корректной работы без передачи параметров. При отсутствии `page` и `size` сервер автоматически возвращает первую страницу (page=0) размером 20 записей (size=20).

В результате, эндпоинт гарантированно возвращает только запрошенный подмножество данных с соответствующими метаданными об общем объеме и номерах страниц, обеспечивая соответствующее поведение при запросах, даже если указанная страница или размер недоступны.
