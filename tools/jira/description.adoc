== ODS-6

//tag::ODS-6[]
=== Реализация бизнес-логики и расширенных сценариев

Сервис управления пользователями получил значительное улучшение функциональности, повысив его надёжность и расширив возможности поиска. Внедрена строгая бизнес-валидация входных данных, которая гарантирует корректность формата email и минимальную длину имени пользователя. Кроме того, реализован механизм аудита, который автоматически фиксирует все действия (создание, обновление, удаление) в отдельной таблице `user_audit`. Улучшена обработка ошибок, что позволяет возвращать структурированные JSON-ответы при возникновении любых исключений. Наконец, добавлена возможность расширенного поиска пользователей по частичному совпадению email и сортировки списка по заданным параметрам.
//end::ODS-6[]

== ODS-10

//tag::ODS-10[]
=== Исправление обработки пагинации в эндпоинте списка пользователей

В рамках данного релиза была устранена критическая ошибка, связанная с обработкой пагинации в эндпоинте «список пользователей» (`GET /api/v1/users`). Теперь система корректно обрабатывает параметры постраничного просмотра, гарантируя, что клиенты получают только запрошенный набор данных, а не полный список. Обновленная логика обеспечивает строгуе соблюдение стандартов пагинации, включая проверку входных параметров: если указан отрицательный номер страницы или размер страницы превышает 100, возвращается соответствующий статус ошибки 400. Кроме того, структура возвращаемого JSON-объекта была унифицирована, включая поля, отражающие общее количество элементов и страниц. По умолчанию, при отсутствии параметров запроса, используется первая страница размером 20 записей.
//end::ODS-10[]
