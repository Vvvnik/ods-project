# Обзор проекта: Сервис управления пользователями (User Management Service)

***Технологический Стек***: Spring Boot (Java) и PostgreSQL.

---

## 💡 Концепция и Общая Обзор

Проект – это поэтапная разработка полного REST API для управления сущностью `Пользователь` (`User`). Система построена по итеративному принципу, где каждая задача является логическим и функциональным продолжением предыдущей.

---

## 📝 ODS-7: Проектирование контрактов REST API (Фаза Дизайна)

**Цель:** Сформировать формальный контракт API, задокументированный в формате *OpenAPI (Swagger)*.

**Основные эндпоинты (CRUD):**

* `POST /api/v1/users`: Создание нового пользователя.
* `GET /api/v1/users/{id}`: Получение данных пользователя по уникальному ID.
* `PUT /api/v1/users/{id}`: Обновление существующих данных.
* `DELETE /api/v1/users/{id}`: Удаление записи.
* `GET /api/v1/users`: Получение списка пользователей (обязательно с пагинацией).

**Ключевые требования к модели:**
Для каждого эндпоинта требуется определить:
1.  HTTP-метод и параметры (path, query, body).
2.  Запрошенные модели данных (JSON-схемы: `UserRequest`, `UserResponse`).
3.  Полный перечень HTTP-кодов и описаний ошибок (акцент на `400`, `404`, `409`).

---

## 💾 ODS-8: Реализация контроллеров и слоев данных (Фаза Ядра)

**Цель:** Реализовать механику работы API и обеспечить надежное и постоянное хранение данных.

**Основные технические блоки:**
1.  **Контроллеры (Java):** Создание контроллеров, которые обрабатывают входящие HTTP-запросы, принимая и возвращая DTO-объекты.
2.  **Слой данных (DAO/Repository):** Использование `Spring Data JPA` для обеспечения базовых операций.
    *   Методы должны включать: `save()`, `findById()`, `findAll()` (с пагинацией), `deleteById()`.
    *   **Критическое требование:** В БД должен быть создан *уникальный индекс* на поле `email`.
3.  **Инфраструктура:** Настройка соединения с *PostgreSQL* и выполнение схемы миграции (`UserEntity`).

---

## 🧠 ODS-9: Бизнес-логика и расширенные сценарии (Фаза Доработки)

**Цель:** Повысить системную устойчивость, добавить сложные бизнес-правила и улучшить UX.

**Основные направления доработки:**
*   **Бизнес-валидация:**
    *   Механизм валидации данных на уровне кода с использованием аннотаций JSR-380 (проверка формата `email`, минимальная длина `name`).
*   **Система аудита (Auditing):**
    *   Создание таблицы `user_audit` в БД.
    *   **Принцип:** Обязательный лог для каждой операции (CRUD) с записью: *кто*, *когда* и *какое действие* выполнено.
*   **Обработка ошибок:**
    *   Внедрение глобального обработчика (`@ControllerAdvice`).
    *   Все исключения должны возвращаться в единый, унифицированный формат JSON.
*   **Продвинутый функционал:**
    *   Поддержка поиска по *частичному совпадению* email.
    *   Возможность *параметризованной сортировки* списка пользователей.




## Общий контекст
Все задачи (`ODS-6`, `ODS-7`, `ODS-8`, `ODS-9`) направлены на разработку полноценного **Сервиса управления пользователями** с использованием стека Spring Boot (Java), PostgreSQL и REST API.

## Описание задач

### 📝 ODS-6: Разработать Сервис управления пользователями (Обзорная / Общая задача)
Это **родительская/мастер-задача**, которая объединяет и координирует работу над всем сервисом.
*   **Цель:** Создать полный REST API для управления пользователями.
*   **Технологии:** Spring Boot (Java), PostgreSQL, Swagger/OpenAPI.
*   **Ожидаемый результат:** Готовое описание работ, разделенное на контракты API, реализацию слоя данных и бизнес-логику.
*   **Зависимости:** Эта задача разбивается на конкретные, более детальные подзадачи (ODS-7, ODS-8, ODS-9).

### 🛡️ ODS-7: Спроектировать и документировать контракты REST API (Контракт-ориентированный этап)
*   **Цель:** Сформировать и верифицировать спецификацию REST API для всех CRUD-операций над сущностью "Пользователь".
*   **Формат:** OpenAPI (Swagger) – ожидается файл `openapi.yaml` или `swagger.json`.
*   **Ключевые элементы:**
    *   Эндпоинты: `POST`, `GET/{id}`, `PUT/{id}`, `DELETE/{id}` для пользователей.
    *   Требования: Определить HTTP-методы, параметры (path, query, body), модели запросов/ответов и коды ошибок (400, 404, 409).
    *   Модель данных `User`: должна включать `id` (UUID), `name`, `email` (unique), `createdAt`, `updatedAt`.
    *   Интеграция с генерацией Swagger UI.

### 🛠️ ODS-8: Реализация контроллеров и взаимодействия с БД (Слой реализации данных)
*   **Цель:** Реализовать рабочие компоненты, которые соответствуют контрактам, определенным в ODS-7, с фокусом на правильную работу с базой данных.
*   **Компоненты:**
    1.  **Контроллеры (`@RestController`):** Обработка HTTP-запросов, принятие/возврат DTO.
    2.  **Репозиторий (DAO/Repository):** Использование Spring Data JPA для операций `save()`, `findById()`, `findAll()` и `deleteById()`.
    3.  **Модель:** JPA-сущность `UserEntity` с маппингом в таблицу `users`.
    4.  **Настройка:** Подключение к PostgreSQL и миграция (Flyway/Liquibase).
*   **Критерии:** Данные должны корректно сохраняться и извлекаться, с правильной обработкой ошибок конфликта (например, email уже существует – 409 Conflict).

### 🚀 ODS-9: Реализация бизнес-логики и расширенных сценариев (Уровень бизнес-правил)
*   **Цель:** Добавить к базовому функционалу бизнес-валидацию, аудит изменений и продвинутые поисковые возможности.
*   **Функционал:**
    1.  **Валидация:** Использование аннотаций JSR-380 (`@Valid, @Email, @NotBlank`) для проверки входных данных (формат email, длина имени).
    2.  **Аудит (Audit):** Создание таблицы `user_audit` и запись каждой CRUD-операции для отслеживания изменений.
    3.  **Обработка ошибок:** Реализация глобального обработчика исключений (`@ControllerAdvice`) для структурированного возврата всех типов ошибок.
    4.  **Расширенный поиск:** Реализация поиска по email с частичным совпадением (`?emailContains=...`) и сортировки списка пользователей (по имени или дате).

***

**Резюме рабочего процесса:**
Проект требует поэтапного подхода: сначала **Контракт (ODS-7)** $\rightarrow$ затем **Основная реализация CRUD и БД (ODS-8)** $\rightarrow$ и наконец, **Улучшение и обогащение функционала бизнес-правилами (ODS-9)**.
