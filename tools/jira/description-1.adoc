== ODS-6

//tag::ODS-6[]
=== User Management Service Release

В ходе релиза осуществлена полная реализация сервиса управления пользователями, включающая:

* В качестве основы использована спецификация OpenAPI‑записанная в openapi.yaml, содержащая все CRUD‑операции, список пользователей с пагинацией, поиск по email и сортировку; Swagger UI доступен по /swagger‑ui.html и отображает все эндпоинты, запросы и ответы.
* Созданы контроллеры UserController, репозитории и сущность UserEntity, реализующие взаимодействие с PostgreSQL через Spring Data JPA; миграции Flyway создают таблицу users с уникальным индексом по email.
* Введены бизнес‑правила: проверка корректности email и минимальной длины имени при помощи JSR‑380 аннотаций, глобальный обработчик исключений (@ControllerAdvice) формирует унифицированные JSON‑ответы с кодами ошибок (400, 404, 409 и др.).
* Реализована запись аудита: таблица user_audit фиксирует действия CREATED, UPDATED, DELETED, а также timestamp и user_id выполняющего действие; каждая CRUD‑операция автоматически генерирует запись аудита.
* Наладлена поддержка пагинации, поиск по частичному совпадению email (GET /api/v1/users?emailContains=…) и сортировка списка по name или createdAt через параметры запроса.
//end::ODS-6[]

== ODS-10

//tag::ODS-10[]
=== Сервис управления пользователями   
 
В релизе реализован полноценный REST‑сервис, включающий:  

* OpenAPI‑спецификацию (openapi.yaml) с CRUD‑операциями, пагинацией, поиском по email и сортировкой списка пользователей;
* Контроллер **UserController**, репозиторий **UserRepository** и сущность **UserEntity** на основе Spring Data JPA;
* Миграцию Flyway: таблица *users* со столбцами *id*, *name*, *email*, *created_at*, *updated_at* и уникальным индексом по *email*;
* Бизнес‑правила: проверка корректности email и минимальной длины имени, глобальный обработчик ошибок, аудит действий (*user_audit*).

Устранена ошибка пагинации (ODS‑10):

* Пересмотрены параметры **page** и **size** в методе `UserController.getUsers`, теперь они передаются в `Pageable`;
* Добавлена валидация:  
**page ≥ 0** – при `page < 0` возвращаем 400 Bad Request с сообщением «Page number must not be less than 0»;  
**size ∈ [1, 100]** – при `size > 100` отвечаем 400 Bad Request с сообщением «Size must be between 1 and 100»;  
при отсутствии параметров используем `page = 0`, `size = 20`;
* Возвращаем JSON‑объект стандартной структуры `Page`:  
**content** – массив пользователей текущей страницы;  
**totalPages** – общее количество страниц;  
**totalElements** – общее число пользователей;  
**size**, **number**, **first**, **last** – параметры текущей страницы;
* Созданы unit‑тесты и интеграционные тесты, проверяющие корректность пагинации, ответы 400  для неверных параметров и структуру JSON‑ответа.

Согласно этим изменениями клиентское приложение теперь может запрашивать пользователей постранично, а сервер гарантирует правильную работу над большими наборами данных.
