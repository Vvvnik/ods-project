## Описание

В текущем реализации эндпоинта GET /api/v1/users обнаружена ошибка в работе пагинации: при указании параметров page и size сервер возвращает некорректный набор данных либо игнорирует параметры. Это приводит к тому, что клиенты не могут получить список пользователей постранично – вместо этого всегда возвращается полный список, что создаёт нагрузку на сеть и клиентское приложение.

### Требования:

#### Исправление логики пагинации:

Пересмотреть реализацию метода контроллера UserController.getUsers(page, size).

Обеспечить корректную передачу параметров пагинации (page, size) в слой доступа к данным (Repository).

Использовать стандартные механизмы Spring Data JPA для пагинации (например, Pageable и Page<T>).

#### Корректное формирование ответа:

Эндпоинт должен возвращать JSON‑объект со следующей структурой:

{

  "content": [...],          // массив пользователей текущей страницы

  "totalPages": 5,       // общее количество страниц

  "totalElements": 100,  // общее количество пользователей

  "size": 20,           // размер страницы (size)

  "number": 0,          // номер текущей страницы (page)

  "first": true,         // флаг – первая страница?

  "last": false          // флаг – последняя страница?

}

Поле content должно содержать только пользователей для запрошенной страницы.

#### Валидация параметров запроса:

Добавить проверку входных параметров page (номер страницы, отсчёт с 0) и size (количество элементов на странице).

Если page < 0, возвращать HTTP‑статус 400 Bad Request с сообщением: "Page number must not be less than 0".

Если size <= 0 или size > 100, возвращать 400 Bad Request с сообщением: "Size must be between 1 and 100".

По умолчанию (если параметры не переданы) использовать page=0 и size=20.

#### Тестирование исправленного функционала:

Написать unit‑тесты для метода контроллера, покрывающие:

корректную работу с разными комбинациями page и size;

обработку крайних случаев (первая, последняя, несуществующая страница);

проверку структуры возвращаемого JSON.

Провести интеграционное тестирование эндпоинта через Swagger UI или Postman:

Убедиться, что при page=0&size=10 возвращается первая десятка пользователей.

Проверить, что при page=999&size=10 (несуществующая страница) возвращается пустой массив content и корректные значения totalPages, totalElements.

Подтвердить, что параметры по умолчанию (без page/size) работают как ожидается (возвращают первую страницу размером 20 записей).

### Критерии приёмки (Acceptance Criteria):

При запросе GET /api/v1/users?page=1&size=5 сервер возвращает HTTP‑статус 200 OK и JSON с 5 пользователями со второй страницы.

При page=-1 сервер возвращает 400 Bad Request и сообщение об ошибке.

При size=150 сервер возвращает 400 Bad Request и сообщение об ошибке.

Без параметров (GET /api/v1/users) сервер возвращает первую страницу (page=0) размером 20 записей (size=20).

Структура JSON‑ответа соответствует описанной в требовании 2.

Unit‑тесты и интеграционные тесты проходят успешно.
