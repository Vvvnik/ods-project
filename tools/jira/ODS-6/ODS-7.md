## Описание

Сформировать спецификацию REST API в формате OpenAPI (Swagger) для CRUD-операций над сущностью "Пользователь".

### Требования

- Создать OpenAPI-спецификацию (openapi.yaml или swagger.json) со следующими эндпоинтами:
- POST /api/v1/users - создание пользователя;
- GET /api/v1/users/
{id} - получение пользователя по ID;
- PUT /api/v1/users/{id}
- обновление пользователя;
- DELETE /api/v1/users/
{id}
- удаление пользователя;

- GET /api/v1/users - получение списка пользователей с пагинацией.

- Для каждого эндпоинта определить:

- HTTP-метод;

- параметры (path, query, body);

- модели запросов и ответов (JSON-схемы для UserRequest, UserResponse, UserListResponse);
- коды HTTP-статусов и описания ошибок (400, 404, 409 и т. д.);
- примеры запросов и ответов.
- Описать модель данных User:
- id (UUID);
- name (string, required);
- email (string, email, unique, required);
- createdAt (timestamp);
- updatedAt (timestamp).

- Интегрировать спецификацию с приложением (например, через SpringDoc-OpenAPI) для генерации интерактивной документации Swagger UI.

### Критерии приемки:

- Существует валидный файл OpenAPI-спецификации.

- Swagger UI доступен по адресу /swagger-ui.html и отображает все эндпоинты.

- Для каждого метода указаны модели данных, коды ответов и примеры.
