## Описание

Добавить в сервис бизнес-правила, расширенную валидацию и механизмы аудита действий над пользователями.

### Требования:

Бизнес-валидация:

	
- Добавить проверку корректности email (формат) и минимальной длины имени (например, 2 символа).
	
- Применить валидацию с использованием аннотаций JSR-380 (@Valid, @Email, @NotBlank).

Аудит действий:

	
- Создать таблицу user_audit в БД с полями:

id;

user_id;

action (CREATED, UPDATED, DELETED);

timestamp;

changed_by (ID пользователя, выполнившего действие).
	
- При каждом изменении сущности User создавать запись в user_audit.

Обработка ошибок:

	
- Создать глобальный обработчик исключений (@ControllerAdvice) для перехвата:

ошибок валидации;

исключений БД (например, DataIntegrityViolationException);

общих ошибок приложения.
	
- Возвращать структурированные JSON-ответы об ошибках с кодом и сообщением.

Расширенные сценарии:

	
- Реализовать поиск пользователей по email (частичное совпадение, GET /api/v1/users?emailContains=...).
	
- Добавить сортировку списка пользователей (по name или createdAt) через параметры запроса.

### Критерии приемки:

	
- Валидация входных данных работает на уровне контроллера и сервиса.
	
- Записи аудита создаются для всех CRUD-операций.
	
- Ошибки возвращаются в едином формате JSON.
	
- Поиск и сортировка по списку пользователей работают согласно спецификации.
