== Что такое ODS?

ODS (Open Documentation Standard) — это стандарт открытой документации, который обеспечивает единообразный подход к созданию, структурированию и генерации технической документации для проектов.

=== Основные принципы ODS

* Модульность — документация разбита на независимые компоненты
* Автоматизация — генерация документации из исходных файлов
* Стандартизация — единые форматы и структуры
* Интеграция — поддержка различных источников данных (API, БД, диаграммы)

== Конфигурация проекта

=== Автоматизация

Процесс сборки полностью автоматизирован через `tools/start.rb`:

[source,bash]
----
ruby tools/start.rb
----

Скрипт выполняет:
1. Генерацию SVG из исходных диаграмм (BPMN, Draw.io)
2. Генерацию AsciiDoc документации (при необходимости)
3. Создание PDF файлов
4. Сборку сайта Antora

== Преимущества ODS

=== Для разработчиков

* Единообразие — стандартизированный подход к документации
* Автоматизация — минимум ручной работы
* Интеграция — связь с исходным кодом и данными

=== Для команды

* Прозрачность — понятная структура проекта
* Масштабируемость — легко добавлять новые компоненты
* Поддерживаемость — централизованная конфигурация

=== Для пользователей

* Актуальность — документация всегда синхронизирована с кодом
* Полнота — покрытие всех аспектов проекта
* Доступность — веб-сайт и PDF версии
* Качество изображений — SVG диаграммы для четкого отображения

== Быстрый старт

ODS использует два независимых процесса:

. Сборка документации — генерация AsciiDoc файлов и PDF из различных источников.
. Сборка сайта — создание HTML сайта из готовых AsciiDoc файлов.

Процессы независимы. Конфигурация Antora не связана с конфигурацией сборки документации.

=== Установка зависимостей

[source,bash]
----
# Docker (рекомендуется)
docker --version

# Или локальная установка:
# Ruby зависимости
gem install asciidoctor asciidoctor-pdf asciidoctor-kroki

# Node.js зависимости
npm install

# PlantUML (для генерации SVG диаграмм)
# Установите PlantUML и Java

# Graphviz (для ERD диаграмм)
# Установите Graphviz

# PostgreSQL (для документации БД)
# Настройте подключение в config.yml
----

=== Быстрое тестирование PDF

Для проверки кастомных конвертеров используйте команду:

=== Кастомные PDF конвертеры

Проект включает специализированные конвертеры для создания PDF документов с различными типами оформления:

==== Типы титульных страниц

[cols="1,2,3"]
|===
|Тип |Атрибут |Описание

|original
|`:custom_title_page: original`
|Стандартная титульная страница с рамками

|approval_sheet
|`:custom_title_page: approval_sheet`
|Лист утверждения с подписями

|table
|`:custom_title_page: table`
|Таблицы из t_titul_doc.adoc

|none
|`:custom_title_page: none`
|Без титульной страницы
|===

==== Использование

Для применения кастомного оформления добавьте соответствующие атрибуты в документ:

[source,asciidoc]
----
= Название документа
:title-page:
:custom_title_page: approval_sheet

Содержимое документа...
----

==== Архитектура конвертеров

* Модульная структура — каждый тип страницы в отдельном файле
* Оптимизация — кэширование атрибутов и батчевая загрузка
* Гибкость — легко добавлять новые типы оформления

==== Динамическая конфигурация конвертеров

Система использует файл конфигурации `tools/config_type_page.yml` для автоматического выбора конвертеров:

[source,yaml]
----
# Конфигурация кастомных PDF конвертеров
title_pages:
  original: "title_page_original"
  approval_sheet: "title_page_approval_sheet"
  table: "title_page_table"
  none: null
----

Принцип работы:
1. Атрибут документа → Тип конвертера (из YAML)
2. Тип конвертера → Модуль (автоматическая загрузка)
3. Модуль → Методы (динамический вызов)

==== Добавление нового типа страницы

Для добавления нового типа страницы выполните следующие шаги:

===== 1. Обновите конфигурацию

Добавьте новый тип в файл `tools/config_type_page.yml`:

[source,yaml]
----
title_pages:
  # ... существующие типы ...
  новый_тип: "title_page_новый_тип"
----

===== 2. Создайте модуль

Создайте файл в папке `tools/lib/` с именем, указанным в конфигурации:

[source,ruby]
----
# tools/lib/title_page_новый_тип.rb
module TitlePageНовыйТип
  def ink_title_page_новый_тип(doc)
    # Ваша логика для титульной страницы
  end
end
----

===== 3. Используйте в документе

Добавьте атрибут в ваш AsciiDoc документ:

[source,asciidoc]
----
= Название документа
:title-page:
:custom_title_page: новый_тип

Содержимое документа...
----

==== Команда сборки PDF

Для сборки PDF с кастомными конвертерами используйте следующую команду:

[source,bash]
----
asciidoctor-pdf \
  -r asciidoctor-kroki \
  -r ./tools/scripts/convert_ascii_to_pdf.rb \
  -a kroki-default-format=png \
  -a kroki-server-url=http://localhost:8000 \
  -a pdf-theme=report \
  -a pdf-themesdir=resources/themes \
  -a pdf-fontsdir=resources/fonts \
  -a allow-uri-read \
  components/{имя_компонента}/modules/{модуль}/pages/{имя_файла}.adoc
----

Параметры:
* `{имя_компонента}` — название компонента (например: `information-system`)
* `{модуль}` — модуль внутри компонента (например: `ROOT`, `trd`)
* `{имя_файла}` — имя файла без расширения (например: `Частное_техническое_задание`)

Пример:
[source,bash]
----
asciidoctor-pdf \
  -r asciidoctor-kroki \
  -r ./tools/scripts/convert_ascii_to_pdf.rb \
  -a kroki-default-format=png \
  -a kroki-server-url=http://localhost:8000 \
  -a pdf-theme=report \
  -a pdf-themesdir=resources/themes \
  -a pdf-fontsdir=resources/fonts \
  -a allow-uri-read \
  components/information-system/modules/trd/pages/Частное_техническое_задание.adoc
----
